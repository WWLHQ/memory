# 踩坑总结 (2026-10-09)

## 1. 跨 iframe 登录态丢失
**现象**: 首页登录后切换到 AgentOnboard 或内联标识页，提示需要重新登录
**根因**: 
- sessionStorage 在不同 iframe 间共享不可靠（同源但不同 URL）
- placeholderContext 没有 sessionId，导致 storeSessionId 无法写入
**修复**: 
- 改用 localStorage 存储 session key `session:realpage`
- placeholderContext 返回 `{context, sessionId}`，确保 storeSessionId 能写入
- TenantProvider 初始化时从 localStorage 恢复 context

## 2. 后端进程不稳定
**现象**: 后端时断时续，E2E 测试失败
**根因**: 
- Windows 下 `&` 后台运行不稳定
- 端口被占用后重启失败
**修复**: 
- 使用 `taskkill //F //PID` 先杀旧进程再启动
- 用 `lsof -ti :8200 | xargs kill` 确保端口释放
- 测试时用 `node --experimental-strip-types tools/dev-backend.mjs` 直接启动

## 3. 浏览器缓存旧 JS
**现象**: 代码已修改，但浏览器仍显示旧行为
**根因**: 
- Vite 构建产物有 hash 文件名，但浏览器缓存了旧文件
- 静态服务器没有设置缓存失效头
**修复**: 
- 强制刷新 `Ctrl+Shift+R`
- 或在开发者工具中勾选 "Disable cache"

## 4. 验证码获取方式
**现象**: E2E 测试中验证码不匹配
**根因**: 
- 前端通过 `window.location.search.get('backend')` 获取后端地址，但测试环境中可能未正确传递
- 验证码是一次性的，测试中容易过期
**修复**: 
- 直接从页面按钮文本中提取验证码（测试用，生产环境不应暴露）
- 或使用 Playwright 的 `page.evaluate` 直接调用后端 API

## 5. 登录态恢复逻辑
**现象**: 切换 iframe 后登录态丢失
**根因**: 
- React 组件重新挂载时 state 重置为 null
- 没有从持久化存储恢复登录态
**修复**: 
- TenantProvider 初始化时检查 localStorage 中的 session
- 有 session 时生成占位 context，避免重复登录

## 6. TypeScript 类型错误
**现象**: `action: 'register'` 不在 LoginAudit action 联合类型中
**根因**: 
- LoginAudit.action 只允许 `'login' | 'login_fail' | 'logout' | 'team_assign'`
**修复**: 
- 注册审计使用 `action: 'login'` 占位（或扩展类型）

## 7. 端口冲突
**现象**: 启动服务时 `EADDRINUSE`
**根因**: 
- 旧进程未完全退出
**修复**: 
- 使用 `netstat -ano | findstr ":8200"` 查找占用进程
- `taskkill //F //PID <pid>` 强制终止

## 8. vitest 5 测试文件静态 import 崩溃（今天最大坑）
**现象**: `import { describe, it, expect } from 'vitest'` 的测试文件全部报 
`TypeError: Cannot read properties of undefined (reading 'config')`（在 describe 行）；
而依赖 `globals: true`（不 import）的测试全部正常。
**根因**: 默认 pool（forks/threads）下 `'vitest'` 被双实例化——runner 内部初始化的 runner 变量
和测试文件静态 import 拿到的不是同一个模块实例，`runner.config` 读取时为 undefined。
疑与 WorkBuddy 定制版 Node 22.22.2 的模块加载有关。
**修复**: `vite.config.ts` 的 `test` 段加 `pool: 'vmThreads'`（同一 VM 上下文共享模块实例）。
**教训**: 出现"import 的 describe 报 config 错"先想到双实例化，直接上 vmThreads，不要逐个试版本降级。

## 9. npm arborist peer 解析 bug
**现象**: `npm install` 报 `Cannot read properties of null (reading 'edgesOut')`；
且 `@testing-library/dom` 等被 peer 依赖的包静默缺失（lock 文件里也没有）。
**修复**: 安装时加 `--legacy-peer-deps`；缺失的包显式 `npm install -D @testing-library/dom@^10 --legacy-peer-deps`。
**教训**: node_modules 行为诡异时先核对 `ls node_modules/@xxx/` 是否缺包，npm 报 arborist 错误就加 --legacy-peer-deps。

## 10. jsdom 30 下 window.location 不可重定义
**现象**: 测试里 `Object.defineProperty(window, 'location', {...})` 报 `Cannot redefine property: location`。
**修复**: 改用 `window.history.replaceState(null, '', '?query=...')` 修改 search 参数（jsdom 原生支持）。

## 11. E2E 全量运行静默 SIGTERM（已破案）
**现象**: `playwright test` 全量运行时进程被 SIGTERM 杀死，无任何输出；单文件运行正常。
**根因（三层叠加）**:
1. Chromium 在首个 CDP 客户端断开后，HTTP 发现端点 `/json/version` 返回 404
   → 后续 worker 的 connectOverCDP 全挂（静默失败）。
2. `browser.close()` 偶发挂起 → worker 进程不退出 → Playwright 300s 后强杀（SIGTERM 来源）。
3. crossTabAuth/register 两个 spec 未走 harness（无 disconnectBrowser），必挂。
**修复**:
- `global-setup.mjs` 预取 `/json/version` 的 `webSocketDebuggerUrl` 存入 .cde.json，
  harness 直接用 `ws://` 连接（绕过会 404 的 HTTP 发现）。
- `harness.ts` disconnectBrowser 加 3s 超时兜底（Promise.race）。
- crossTabAuth/register 重构为自包含（自带 startStatic + home server + 独立端口 8128/8129、8204/8205）。
- `package.json` test:e2e 加 `--workers=1`（串行 + 各 spec 独立端口，最稳）。
**教训**: "SIGTERM 无输出" = worker 退出被吊住，去查 teardown 里的挂起句柄（CDP/keep-alive socket）。

## 12. E2E 用例与登录门控脱节
**现象**: Overview 加登录门控后，overview.spec 直接点导航 → 触发 alert 回到登录视图 → 断言 iframe src 失败。
**修复**: 测试里用 `page.addInitScript(() => localStorage.setItem('session:realpage', 'xxx'))` 模拟已登录；
同时把断言从 `#btnOpenLogin`（未登录）改为 `#btnLogout`（已登录）。
**教训**: 改了登录门控/鉴权逻辑后，所有相关 E2E 必须同步更新"预置登录态"步骤。

## 13. CORS 白名单漏新请求头（真实 BUG）
**现象**: E2E 登录总是走"本地只读占位"回退，team_id=local-readonly；curl 直连后端却正常。
**根因**: 前端跨 iframe 改造后 fetch 带上 `X-Auth-Session` 头，
但 `src/home/server.ts` 的 `Access-Control-Allow-Headers` 只允许 `Content-Type,x-session-id`
→ 预检失败 → fetch net::ERR_FAILED → 前端回退占位。curl 不发预检所以正常。
**修复**: 白名单加上 `x-auth-session`。
**教训**: "curl 正常但浏览器失败"九成是 CORS 预检；新增自定义请求头必须同步后端白名单。
