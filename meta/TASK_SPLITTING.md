# 任务拆分规范（原子任务 · 供 Agent 执行）

> 目的：把"项目计划与任务拆分"阶段产出为**可独立验证的原子任务**，让 Agent 每次只拿最小上下文就能准确完成，且不越界乱改。
> 拆分的第一原则：**让 Agent 能很好、准确地完成每一项任务**——不是拆给人看，是拆给模型吃。

---

## 原子任务的 8 项必备属性

每个原子任务开工前必须写明以下 8 点，**缺一项不许开工**：

1. **单一目标**：只做一件事。
   - ✅ "实现密码哈希函数"  ❌ "实现用户注册"（含太多子目标）
2. **输入明确**：依赖哪些文件 / 接口 / 类型 / 数据 / 文档。Agent 据此**只加载这些**。
3. **输出明确**：新增或修改哪些文件，产出什么函数 / API / 组件 / 测试。
4. **验收可执行**：能用 1~几条命令判定完成，如 `npm test -- register`。红 = 没做完。
5. **修改边界清晰**：只允许改哪些目录 / 文件，越界即违规（Agent 自我约束 + CI 检查）。
6. **依赖明确**：前置任务是谁、被谁依赖，形成 DAG（有向无环图）。
7. **上下文可控**：相关文件不超过模型窗口 30%~50%，否则**继续拆**。
8. **可独立提交 / 回滚**：一个任务 = 一个 PR 或一个 commit。

---

## 任务文件模板

```markdown
## T{n} {任务名}
- 目标：{单一目标}
- 输入：{文件 / 接口 / 类型 / 数据 / 文档}
- 输出：{新增或修改的文件 + 产出物}
- 验收：{命令，如 npm test -- register}
- 边界：仅允许修改 {目录 / 文件}
- 依赖：前置 {Tx, Ty}；被 {Tz} 依赖
- 提交：一个 PR/commit，message 含 T{n}
```

## 拆分层级推荐（示例：用户注册）

> 以下仅为**示例**，必须"理解真实需求后重新创作"。恒定原则：越底层越先、越纯越先；UI / 集成 / E2E 靠后；每个任务都能被一条命令验收。

- **T1** 初始化项目骨架、lint、test（脚手架 + 工具链）
- **T2** 定义 User 类型 + DB schema（数据契约）
- **T3** 数据库迁移（migrate）
- **T4** 实现 `hashPassword` + 单测（纯函数，零依赖）
- **T5** 实现 `UserRepository.create` + 单测（依赖 T2/T3）
- **T6** 实现 `RegisterService` + 单测（依赖 T4/T5）
- **T7** 实现 `POST /api/register` + 集成测试（依赖 T6）
- **T8** 前端注册表单组件（依赖 T7 的 API 契约）
- **T9** 前端 API client（依赖 T7）
- **T10** 端到端注册测试（依赖 T6~T9）

完整填好的 8 字段示例见 [`specs/tasks/USER-REGISTER.md`](specs/tasks/USER-REGISTER.md)。

## 与门禁的关系

- 每个任务自带"验收命令"= 该任务的单元 / 集成测试。
- 任务完成后仍跑 `python tools/validate_project.py`，确认没破坏索引契约 / 编号对应。
- 全部任务绿 + validate 绿 = 本阶段完成。
