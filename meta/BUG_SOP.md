# BUG 处理 · 事中流程 SOP

> 对应流程第 10/11 步（生产运维与监控 / 反馈与迭代）。规定 Agent 接到一个 BUG 时的标准执行动作。
> 建立在"事前准备"之上：准备做足，定位从"搜全项目"变成"看一眼 code-map + 红测试"。
> 配套：事前准备 [`meta/DEBUG_READINESS.md`](meta/DEBUG_READINESS.md)；可追溯映射 [`specs/code-map.md`](specs/code-map.md)。

---

## 一、总原则
- **上下文可控**：只加载出问题那一个模块（由 code-map 定位），不拉全项目。
- **先复现后修**：没有可复现，不轻易改。
- **测试先行**：先写失败测试锁定 BUG，再修。
- **外科修复**：只改边界内，不整体重写。
- **沉淀**：修完更新 `known-issues.md` 与 `CHANGELOG.md`（首次使用即创建）。

---

## 二、标准流程（7 步）

1. **接报**：拿到现象 + 报错（含 `traceId` / 日志 / 堆栈 / 复现步骤）。
2. **定位模块**：用 `code-map.md` 或红测试，确定 `REQ` / `TC` → 文件 / 函数（只锁定一个模块）。
3. **最小复现**：写最小可跑用例复现（单测或脚本），证明 BUG 确实存在。
4. **先写失败测试**：把复现固化为一个失败测试（新增 `BUG-xxx` 用例或对应 `TC`）。
5. **外科修复**：只在边界内做局部 Edit，跑到该测试绿。
6. **跑门禁**：`python tools/validate_project.py` 全绿 + 全量测试无回归。
7. **沉淀 + 提交**：更新 `known-issues.md`（症状 → 模块 → 根因 → 修复）、`CHANGELOG.md`；一个 commit，message 含 BUG 编号 / `REQ`。

---

## 三、给 Agent 的指令模板（复制即用）

```
修复 BUG：现象=...，报错=...（traceId=...）。
1) 用 specs/code-map.md 定位到模块与文件；
2) 只加载该模块相关文件，不读全项目；
3) 先写最小复现的失败测试（锁定 BUG）；
4) 外科修复到测试绿；
5) 跑 `python tools/validate_project.py` + 全量测试，确认无回归；
6) 更新 known-issues.md 与 CHANGELOG.md，一个 commit 含 BUG 编号。
不要顺手重构无关代码，不要只改表象不查根因。
```

---

## 四、红线（禁止）
- ❌ 没复现就改代码。
- ❌ 顺手重构 / 整体重写无关代码。
- ❌ 只改表象不查根因（同一 BUG 二次出现）。
- ❌ 修复后不补测试（下次回归抓不到）。
- ❌ 不更新 `known-issues.md`（同类 BUG 重复分析）。

---

## 五、与事前准备的关系
- `DEBUG_READINESS.md` 让"定位"秒级；本 SOP 让"处置"标准化。
- 若事前没埋线索（无 code-map / 日志）：先补线索再修，并把缺口记入 `known-issues.md`。

---

## 六、完成判据
- 失败测试转绿 **且** 全量测试无回归 **且** `validate` 绿 **且** `known-issues` / `CHANGELOG` 更新 **且** 单 commit = 完成。
