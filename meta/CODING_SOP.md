# 编码开发 · 逐任务执行 SOP

> 对应流程第 6 步（编码开发）/ 阶段 7。本 SOP 规定 Agent 每领到一个原子任务（如 T4）时的标准执行动作，确保"只读该读、只改要改、改完证明没改坏"。
> 配套：任务长什么样见 [`meta/TASK_SPLITTING.md`](meta/TASK_SPLITTING.md)，填写示例见 [`specs/tasks/USER-REGISTER.md`](specs/tasks/USER-REGISTER.md)。
> 主流程（串起拆分→编码→自检→人工验收→提交）：见 [`meta/WORKFLOW_SOP.md`](meta/WORKFLOW_SOP.md)。
> 注意：本 SOP 第 7 步「提交」在编码阶段只保证验收绿 + validate 绿；正式 commit 推迟到主流程第 ⑥ 步（人工验收后）统一做。

---

## 一、执行总原则（源自原子任务 8 属性）
- **上下文可控**：仅加载任务"输入"字段列出的文件，不读全项目。
- **修改边界**：仅改"边界"字段列出的目录 / 文件，不碰其他模块。
- **验收可执行**：以任务"验收"命令为完成判据，红 = 没做完。
- **可独立提交**：一个任务 = 一个 commit / PR。

---

## 二、标准执行循环（7 步）

1. **领任务**：明确 `T{n}` 与单一目标（不是"实现注册"，是"实现 hashPassword"）。
2. **读输入**：只打开任务"输入"字段指定的文件 / 文档（接口、类型、schema、需求）。
3. **定契约**：确认输出物签名（函数 / API / 组件接口），**先写失败测试（TDD）**。
4. **外科实现**：只在"边界"内做局部 Edit，不整体重写、不碰边界外文件。
5. **跑验收**：执行任务"验收"命令，必须全绿；红则修到绿，禁止跳过。
6. **跑门禁**：`python tools/validate_project.py` 必须 0 失败（确认没破坏索引契约 / 编号对应）。
7. **提交**：一个 commit，message 含 `T{n}` 与目标，如 `feat(T4): hashPassword`。

---

## 三、给 Agent 的指令模板（复制即用）

```
执行任务 T4（实现密码哈希函数）。
1) 先读 specs/tasks/USER-REGISTER.md 中 T4 的「输入 / 边界 / 验收」字段；
2) 只加载"输入"列出的文件，只在"边界"列出的目录内修改；
3) 先写失败单测，再外科实现；
4) 完成后跑 `npm test -- hash` 与 `python tools/validate_project.py`，必须全绿；
5) 最后单独一个 commit，message 含 T4。
不要读取或修改边界外的任何文件。
```

> 替换 `T4` 与对应命令即可套用任意任务。

---

## 四、红线（禁止）
- ❌ 读取 / 修改"边界"外的文件。
- ❌ 整体重写相关文件（用局部 Edit）。
- ❌ 跳过验收命令直接声称完成。
- ❌ 把多个任务合并到一个 commit（破坏可回滚）。
- ❌ 上下文超限（相关文件 > 窗口 50%）仍硬做 —— 停下来要求把任务**再拆**。

---

## 五、与任务拆分的关系
- 任务清单来自 `meta/TASK_SPLITTING.md` + `specs/tasks/*.md`。
- 拆分规范 = "任务长什么样"；本 SOP = "怎么执行单个任务"。
- 两者 + `validate` 门禁 = 编码阶段完整闭环。

---

## 六、完成判据
- 该任务：验收命令绿 **且** `validate` 绿 **且** 单 commit = 完成。
- 全部 `T` 完成 = 编码阶段完成，进入"测试验证"（阶段 8）。
