# 会话采集启动指南

> 适用：桌面应用（Electron 打包态，Windows）。
> 本应用启动后**自动**起 8202（MCP TCP）+ 8204（MCP HTTP）+ 8203（Webhook），无需手动开服务；你只需"把 Agent 接上去"。
> ⚠ 8202 / 8204 / 8203 全部需要 **MCP 访问令牌**（见 §0.1；批次26 起 Webhook 与 MCP 同一令牌，无令牌一律 401，带不受信浏览器 Origin 一律 403）。

---

## 0. 前置：应用已启动

启动「多Agent记忆助手」桌面应用。应用主进程会同时起：

| 端口 | 服务 | 协议 |
|---|---|---|
| 127.0.0.1:8202 | MCP 工具服务（`recall_memory` / `write_memory` / `get_user_preferences`） | JSON-RPC 2.0 over TCP（换行分隔 JSON），需令牌 |
| 127.0.0.1:8204 | 标准 MCP streamable-http（`POST /mcp`） | HTTP/JSON，需 `Authorization: Bearer` |
| 127.0.0.1:8203 | Webhook 采集端（`POST /ingest`） | HTTP/JSON，需 `Authorization: Bearer` 或 `x-mcp-token`（批次26 起） |

两者共享同一份 `FileStorage`，Agent 推入的数据与 UI 看到的账本同源。账本位置按运行方式二选一：

- 安装包版：`%APPDATA%\MultiAgent Memory\memories.db.json`
- 便携包 / 开发态：`%APPDATA%\multi-agent-memory\memories.db.json`

> 端口冲突（8202/8203/8204 被占）：主进程只写诊断日志，**不会退避换端口**。若启动失败请手动释放端口或改 `src/electron/main.ts` 里的 `MCP_PORT` / `MCP_HTTP_PORT` / `WEBHOOK_PORT`。

### 0.1 MCP 访问令牌（8202 / 8204 / 8203 必填）

首次启动时应用生成 32 字节随机令牌并持久化：

```
安装包版：    %APPDATA%\MultiAgent Memory\mcp-token.txt
便携包/开发态：%APPDATA%\multi-agent-memory\mcp-token.txt
```

（文件夹名即 Electron `userData` 目录，与账本 `memories.db.json` 同目录。）

- 令牌只写这个文件（权限 0600），主进程日志与审计**绝不记录明文**；把它配置给你的 Agent 即可。
- 丢失/泄露：关闭应用后删除该文件，重启应用会生成新令牌（旧令牌立即失效）。
- TCP：在 `initialize`（或任意请求）的 `params.token` 中携带；该连接后续请求自动继承授权。
- HTTP（8202/8203/8204 通用）：`Authorization: Bearer <token>` 或 `x-mcp-token: <token>`。
- 无令牌/错误令牌 → 拒绝（TCP JSON-RPC `-32001`，HTTP 401）；带不受信浏览器 `Origin` 的请求一律 403。
- 本机 MCP 不接受跨租户身份：`write_memory.user_id` / `get_user_preferences.user_id` 必须等于本机会话用户，否则报错。

## 1. Webhook 通道（主通道，§19.3）

### 1.1 推一条会话事件

Agent 侧发 HTTP：

```bash
curl -X POST http://127.0.0.1:8203/ingest \
  -H 'Content-Type: application/json' \
  -d '{
    "content": "线上事故复盘：支付接口超时，根因是连接池配置 pool_size=5 过小。联系人：张三，电话 13800138000。",
    "project_id": "P1",
    "session_id": "sess-demo-001",
    "source_agent": "claude-code",
    "category": "pitfall",
    "l0_password": "l0pass"
  }'
```

返回：

```json
{
  "ok": true,
  "dedup": "new",
  "hash": "<sha256-hex-64>",
  "mem_id": "mem_xxx",
  "l2_preview": "[...][来源:Agent会话][类型:pitfall] 线上事故复盘…",
  "ts": "2026-…T…Z"
}
```

**幂等**（§5.4）：相同 `content + session_id` 再推一次 → `dedup: "duplicate"`，不会重复入库。

### 1.2 查询最近 N 条（5min 对账窗口）

```bash
curl -H "x-mcp-token: $(cat '%APPDATA%/MultiAgent Memory/mcp-token.txt')" 'http://127.0.0.1:8203/ingest/status?n=20'
# → { "ok": true, "items": [ ... 最近 20 条 ingest 结果（只含 id 与状态，不含正文；n 钳制 1..100）... ] }
```

### 1.3 按 hash 幂等查询

```bash
curl -H "x-mcp-token: $(cat '%APPDATA%/MultiAgent Memory/mcp-token.txt')" 'http://127.0.0.1:8203/ingest/hash?=<上一步返回的 hash>'
# → { "ok": true, "found": true, "result": { ... 该 hash 的 ingest 结果（只含 id 与状态，不含正文）... } }
```

### 1.4 字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| `content` | ✅ | 会话原文（会走 L0 AES-256-GCM 加密 + L1–L6 阶梯精炼） |
| `project_id` | ✅ | 项目 ID（R2 红线） |
| `session_id` | 建议 | 幂等键的一部分（§5.4） |
| `source_agent` | 建议 | 来源 Agent 名（层级页会打「📡 {agent}」徽标） |
| `category` | 可选 | `pitfall`/`decision`/`fact`/`context`/`preference`/`insight`，缺省 `pitfall` |
| `l0_password` | 可选 | ≥6 位；不提供则 L0 降级为 `ENC(...)` 标记串（不可解密） |

## 2. MCP 通道（补偿通道，§19.5）

### 2.1 协议

JSON-RPC 2.0 over TCP，**每行一个 JSON**（换行分隔，非 LSP 的 `Content-Length` 头）。

### 2.2 工具清单

| 工具 | 必填参数 | 可选参数 |
|---|---|---|
| `recall_memory` | `project_id`, `query` | `top_k`（1–10）、`scene`（default/critical/task_start）、`mode` |
| `write_memory` | `content`, `project_id` | `category`、`user_id`、`session_id`、`l0_password`、`source_agent` |
| `get_user_preferences` | `user_id` | — |

### 2.3 示例调用

**写入一条记忆**（等价于 Webhook `POST /ingest`）：

```json
{"jsonrpc":"2.0","id":1,"method":"write_memory","params":{
  "token":"<MCP_TOKEN>",
  "content":"线上事故复盘：支付接口超时，根因是连接池 pool_size=5 过小。",
  "project_id":"P1",
  "session_id":"sess-demo-001",
  "source_agent":"claude-code",
  "l0_password":"l0pass",
  "category":"pitfall"
}}
```

**响应**（成功）：

```json
{"jsonrpc":"2.0","id":1,"result":{
  "mem_id":"mem_xxx",
  "dedup":{"action":"new","sim":0},
  "layers":{"content_l1":"…脱敏后…","content_l2":"…","content_l3":"…","content_l4":"…","content_l5":"…","content_l6":"…"},
  "audit":{"request_id":"req_xxx","action":"write"}
}}
```

**响应**（参数错，缺 `project_id`）：

```json
{"jsonrpc":"2.0","id":1,"error":{"code":-32602,"message":"write_memory.project_id 必填（R2）"}}
```

### 2.4 握手

```json
{"jsonrpc":"2.0","id":0,"method":"initialize","params":{"token":"<MCP_TOKEN>"}}
# → { "result": { "serverInfo": {"name":"memagent-mcp","version":"1.0.0"}, "protocolVersion":"2.0", "capabilities":{"tools":{}} } }

{"jsonrpc":"2.0","id":0,"method":"tools/list"}
# → 三个工具的 schema 清单（同一连接在 initialize 携带 token 后即授权）
```

> 未携带 token（或 token 错误）→ `{"error":{"code":-32001,"message":"unauthorized: 缺少或无效的 MCP token"}}`。

### 2.5 用 `tools/call` 包装调用（可选）

```json
{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{
  "token":"<MCP_TOKEN>",
  "name":"write_memory",
  "arguments":{"content":"…","project_id":"P1","session_id":"sess-demo-001"}
}}
```

### 2.6 标准 MCP HTTP（8204，供不支持私有 TCP 的客户端）

协议：MCP streamable-http，`POST /mcp`，JSON 响应。必须携带令牌；带 `Origin` 的浏览器请求一律 403。

```bash
# Git Bash；便携包/开发态把目录换成 multi-agent-memory
TOKEN=$(tr -d '[:space:]' < "$APPDATA/MultiAgent Memory/mcp-token.txt")

curl -X POST http://127.0.0.1:8204/mcp \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

`initialize` / `tools/list` / `tools/call` 与 §2.2–2.5 相同；`tools/call` 的 `params` 形如 `{"name":"write_memory","arguments":{…}}`。

### 2.7 快速联调脚本（Windows PowerShell）

```powershell
# 令牌：安装包版用 MultiAgent Memory，便携包/开发态换成 multi-agent-memory
$token = (Get-Content "$env:APPDATA\MultiAgent Memory\mcp-token.txt" -Raw).Trim()

$sock = [System.Net.Sockets.TcpClient]::new('127.0.0.1', 8202)
$stream = $sock.GetStream()
$enc = [System.Text.Encoding]::UTF8

function Send($obj) {
  $json = $obj | ConvertTo-Json -Depth 10
  $bytes = $enc.GetBytes($json + "`n")
  $stream.Write($bytes, 0, $bytes.Length)
  $stream.Flush()
  # 读一行
  $sb = New-Object System.Text.StringBuilder
  while (-not $sb.ToString().EndsWith("`n")) {
    $b = $stream.ReadByte()
    if ($b -lt 0) { break }
    $sb.Append([char]$b) | Out-Null
  }
  $sb.ToString().Trim() | ConvertFrom-Json
}

# initialize 携带 token；该连接后续请求自动继承授权
Send @{ jsonrpc='2.0'; id=0; method='initialize'; params=@{ token=$token } }
Send @{ jsonrpc='2.0'; id=1; method='tools/list' }
Send @{ jsonrpc='2.0'; id=2; method='write_memory'; params=@{
    content='MCP 联调：连接池 pool_size=5 过小';
    project_id='P1';
    session_id='sess-mcp-demo-001';
    source_agent='claude-code';
    l0_password='l0pass';
    category='pitfall'
} }

$sock.Close()
```

> 注意：每个 TCP 连接是**独立 Session**（不再共用一个全局会话），连接之间互不串数据；同一连接内仍按行串行处理。
> 连接**首条请求**必须携带 `params.token`（`initialize` 最自然），否则直接返回 `-32001`。

## 3. 一键接入 + 双通道状态机（§19.9 / §19.3）

在桌面应用里：

1. 打开 **Agent 接入配置页**（`agentonboard.html`，概览页的「Agent 接入」入口）。
2. 点 **「⚡ 自动发现并接入本机 Agent」**：
   - 扫 MCP 注册表 / 本机进程 / Webhook 心跳 / 手动兜端点
   - 自动打 P0/P1/P2 徽标，按 19.4/19.5 默认值绑定
   - 逐个 `testConnect`（写 `auto_bind` 审计）
   - 卡片状态机：`CONNECTED` / `DEGRADED`（主通道熔断 → 仅补偿）/ `DISCONNECTED`
3. 单卡片：
   - 「测试接入」→ 真实打后端，返回 RTT + via=backend/local
   - 「轮换密钥」→ 写 `rotate` 审计
   - 勾选「主 Webhook」/「补偿 API 拉取」→ 至少开一（R4 红线）
4. 保存配置 → 后端 `POST /agents`（`agentOnboard` 服务，端口 8200）。

> ⚠ **一键接入只负责"配置 + 审计"，不替 Agent 推事件**。真正推入会话的动作，Agent 侧要调上面的 MCP 工具或 Webhook 端点。

## 5. 故障排查

| 症状 | 排查 |
|---|---|
| `curl 127.0.0.1:8203` 返回 401 | 未带 `x-mcp-token` 头（批次26 起必带，见 §0.1） |
| `curl 127.0.0.1:8203` 拒绝连接 | 应用未启动 / 主窗口没开（`win.on('closed')` 会 close webhook）。看应用主进程 console 是否打印 `[webhook] 监听 127.0.0.1:8203` |
| `curl 127.0.0.1:8202` 拒绝连接 | 同上，看 `[mcp] 监听 127.0.0.1:8202` |
| MCP TCP 返回 `-32001` | 连接首条请求没带 `params.token` 或令牌错误；到 userData 的 `mcp-token.txt` 取最新值（换过令牌记得同步 Agent 配置） |
| MCP HTTP 返回 401 | `Authorization: Bearer <token>` / `x-mcp-token` 缺失或错误；响应头 `WWW-Authenticate: Bearer` |
| MCP HTTP 返回 403 `origin_not_allowed` | 请求带了浏览器 `Origin` 头；本机服务只接受无 Origin 的客户端（curl / MCP SDK） |
| 任意本机接口返回 413 `payload_too_large` | 请求体超过 1 MiB（home / agentOnboard / MCP HTTP；MCP TCP 为单行 1 MiB，超限回 `-32600` 并断开） |
| Webhook 返回 500 | 看 `error` 字段；通常是 `coreWrite` 里 L0 加密失败（`E_CRYPTO`，环境无 WebCrypto） |
| `dedup: "duplicate"` 但你以为是新会话 | 检查 `content + session_id` 是否完全相同；不同 `session_id` 同 content → 幂等键不同，但 `coreWrite` 内容去重仍可能判 `merged` |
| 层级页「⚡ 采集」过滤结果为空 | 确认 `source_agent` 字段非 `manual`；手动写入页不带 `source_agent` → 归「✍️ 手动」 |
| L0 明文查不出来 | L0 需授权密码；层级页密码框 ≥6 位；错密码 → `E_AUTH_L0` + `l0_view` 审计留痕 |

## 6. 最小可运行 Demo（一条命令起 Agent 侧推送）

假设应用已启动，Agent 侧要推一条会话进来：

```bash
# Webhook（推荐，最简）
curl -X POST http://127.0.0.1:8203/ingest ^
  -H 'Content-Type: application/json' ^
  -H 'x-mcp-token: <见 §0.1 令牌文件>' ^
  -d "{\"content\":\"demo 会话：pool_size 调整\",\"project_id\":\"P1\",\"session_id\":\"s1\",\"source_agent\":\"workbuddy\",\"l0_password\":\"l0pass\"}"
```

然后开「记忆层级管理页」→ 顶部过滤「⚡ Webhook」→ 就能看到这条记录，L0–L6 全层可读。喵呜~ (｡･ω･｡)
