# 日志记录页（P15）— 字段级交互规格

> 配套：《需求规格书》4.3（审计）、18.2-E（request_id）、5.2（熔断）、9.7（冲突裁决）、19.10/19.11（端谱/同步）。
> 新增第 15 页「日志记录」：在页面查阅**运行日志 + 异常**，全动作可查、可跳审计。L0 查阅授权也在本页（及记忆管理页）落点。
> 原则：**所有动作都记录、可查、可归因到端与 request_id**（19.11 红线"全动作写审计"）。

## 0. 页面定位与入口

- **P15 日志记录页**：运维/用户自查"记忆助手干了什么、哪里出错了"。与"审计页"（request_id 链路，P11）互补——审计页看**单条记忆的全链路**，日志页看**系统事件流 + 异常**。
- **P15 是"整个软件所有动作"的记录页**：数据源 = `software.log`（运行日志，全动作：recall/write/gc/sync_*/llm_*/l0_view/login/team_assign…，对应 4.3.1 审计动作枚举全量），**不是只记异常**。
- 入口：全局导航「日志记录」；监控页（P6）告警条目可一键跳本页对应过滤。
- **审计日志查阅**：审计（`audit.log`）**不单独常驻显示窗口**——P15 点某条日志的"查阅审计"才**弹出审计窗口**（独立 modal，P11 形态），供查阅该 request_id 全链路；关闭即收起，不常驻。
- **保存与删除策略**（4.3.2）：`software.log` 与 `audit.log` **同目录独立文件**（`<安装根>/logs/`）；软件日志可滚动删除（普通权限），**审计日志 append-only 禁止简单删除**，删除/归档需 **Admin 权限 + 二次确认 + 删除动作本身写审计（`action=audit_delete`）**。

## 1. 日志数据模型（`ma.logs` 返回项，见 API 契约 §4.2）

| 字段 | 类型 | 说明 |
|---|---|---|
| `ts` | 时间 | 事件时间（本地 + UTC 双显） |
| `level` | info/warn/error | 级别；**error 置顶** |
| `form` | 端（19.10） | desktop/web/mobile/mac/linux/cli |
| `action` | 枚举 | recall/write/gc/auto_bind/unbound/sync_up/sync_down/sync_reconcile/conflict_resolve/llm_proxy/llm_fallback/l0_view/… |
| `agent`? | string | 涉及 Agent（auto_bind/llm_proxy 时） |
| `request_id` | string | 审计链主键（18.2-E），可跳审计页 |
| `message` | text | 人读摘要 |
| `ref_audit` | string | 关联审计记录 |
| `extra` | json | 详情（本次花费/命中数/裁决结果/异常堆栈摘要） |

## 2. 字段级交互

### 2.1 过滤区（顶部）
| 控件 | 默认 | 联动 | 异常态 |
|---|---|---|---|
| 级别 | 全部 | info/warn/error 单选；**error 高亮** | — |
| 端 `form` | 全部 | 按当前端默认；可查其他端（跨端对照） | 选"无数据的端"→空态 |
| 动作 `action` | 全部 | 枚举多选（含 sync_*/llm_*/l0_view） | — |
| 时间窗 | 最近 24h | 5min/1h/24h/7d/自定义；**每日全量对账**结果落在 24h/7d | 超 7d 需后台查询 |
| 关键词 | 空 | 搜 request_id / mem_id / agent / 消息 | 无匹配空态 |
| 仅异常 | 关 | 开=只看 error + 告警（熔断/同步失败/额度超限） | — |

### 2.2 日志列表
| 元素 | 行为 | 文案 |
|---|---|---|
| 行 | 时间 · 级别色点 · 端徽标 · 动作 · 消息 · request_id | error 行红底 |
| request_id 链接 | 点击 → 开**审计页**定位该链路（18.2-E） | "查看全链路" |
| 异常行 | 展开 `extra`（异常堆栈摘要/裁决双方版本/额度余量） | "详情" |
| 置顶逻辑 | **error 恒置顶**，同级按 ts 倒序 | — |
| 分页/游标 | `next_cursor` 翻页（`ma.logs.limit`） | "加载更多" |

### 2.3 异常分类（level=error，置顶，按类型聚合）
| 类型 | 触发 | 处置入口 |
|---|---|---|
| 熔断 OPEN | 5.2 主通道连续失败≥5 | 跳 P10 Agent 接入页该 Agent 卡 |
| 同步失败 | `sync_fail`（对账/回传异常） | 看 extra（哪端/哪条/原因），"重试同步" |
| 反代理额度超限 | 19.8 某源额度满 | 跳 P13 大模型配置该用途 |
| L0 解密失败 | 授权/密码错 | "重新授权" |
| 向量后端报错 | Rust/WASM 异常 | "回退 JS 实现" |
| 冲突挂起 | 9.7 自动裁决失败 | 跳 P8 裁决页 |

### 2.4 L0 查阅授权（本页 + 记忆管理页落点）
| 场景 | 交互 | 红线 |
|---|---|---|
| 非管理员看 L0 | L0 列恒遮罩 `[L0 已加密 · 需授权]` | 不泄露明文 |
| 管理员看 L0 | 弹密码框 → 输入 → 解开（本次会话有效） | **每次 `l0_view` 写审计**（4.3） |
| 密码错 | 提示"密码错误，已记审计"，连续 5 次锁定 15min | 审计 `l0_auth_fail` |
| 被授权的非管理员 | 管理员可授权指定 user 查 L0（仍须密码） | 授权动作记审计 |

## 3. 校验规则（前端）

1. **R-LOG1**：level=error 恒置顶，不可被时间窗过滤掉（独立"异常"快捷 Tab）。
2. **R-LOG2**：每条日志必带 `request_id`（无则前端补 `n/a` 且告警——动作没记审计是严重 bug）。
3. **R-LOG3**：L0 查阅**必须**走授权 + 密码，密码不回显、仅存本次会话。
4. **R-LOG4**：跨端查询默认限当前账号（同 user_id/team_id），不跨账号。
5. **R-LOG5**：日志保留期可配（默认 30 天），超期归档不删（审计 4.3）。
6. **R-LOG6（审计查阅非常驻）**：审计日志**不单独常驻窗口**，仅点击某日志"查阅审计"时**弹出独立 modal**（P11 形态），关闭即收起；避免审计界面常驻打扰。
7. **R-LOG7（日志/审计同目录独立文件）**：`software.log` 与 `audit.log` 保存于同一 `<安装根>/logs/` 目录、**独立文件**；软件日志可滚动删除，**审计日志 append-only**。
8. **R-LOG8（审计禁止简单删除，需权限）**：审计日志界面**无普通删除按钮**；删除/归档需 **Admin 权限 + 二次确认**，且删除动作本身写审计 `action=audit_delete`（记录删除者/时间/范围），**删除不可无痕**（保留删除记录）。

## 4. 验收用例

| 用例 | 操作 | 期望 |
|---|---|---|
| 查全动作 | 默认视图（非仅异常） | 可见全软件所有动作（recall/write/gc/sync_*/llm_*/login/team_assign…），不只异常 |
| 查异常 | 开"仅异常" | 只看 error + 告警，置顶，可分类跳对应处置页 |
| 跨端对照 | form 选 web，看同步事件 | 见 `sync_down`/`sync_fail`，归因到 web 端 |
| 弹审计 | 点某行"查阅审计" | **弹出独立 modal** 定位该 request_id 全链路；关闭收起（非常驻） |
| L0 授权 | 非管理员看 L0 | 遮罩；管理员授权后输密码解开，`l0_view` 记审计 |
| 密码错锁定 | 连错 5 次 | 锁 15min，记 `l0_auth_fail` |
| 审计删除 | 普通用户看审计区 | 无删除按钮；Admin 删除需二次确认，写 `audit_delete` 且不可无痕 |
| 保留期 | 配 30 天 | 超期软件日志归档；审计归档需 Admin 权限 |
