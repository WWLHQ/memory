## 二、新增「自动 / 手动」顶层开关 + 调度层实现方案

### 2.1 顶层开关定义（按用户拍板）

模式选择只有**两个顶层档位**，不再把 6 个值平铺给用户：

- **自动（`auto` / `null`）**：Agent 按 `scene × 关键词` 自动分配 5 种具体模式之一（§2.4.4）。这是**默认档**。
- **手动**：用户/宿主**显式指定** 5 种具体模式之一（顶层洞察优先 / 事实优先 / 事件复盘 / 模式推理 / 极简轻量）。未指定具体模式（只选了「手动」没选具体值）视为边界错误，API 校验报错。

> 这样 `mode` 请求的语义收敛为：传 `auto`/`null`=自动；传 5 个 concrete 之一=手动；其余非法。

### 2.2 调度层模块（已落地 `recallModes.ts`）

纯函数、不读存储不调 LLM，单一真源，便于单测与 7.2 自生长引擎热更词表。

**导出 API：**
- `RECALL_MODE_SPECS: Record<ConcreteMode, RecallModeSpec>` —— 5 模式配置（selectPriority / trimOrder / preload / conflictRule / weights / bestFor / disabledLayers / isMinimal），直译 §2.4.3。
- `COMMON_INVARIANTS` —— §2.4.2 公共不变量（所有模式共用，模式不得覆盖）。
- `MODE_FEATURE_WORDS` + `SCENE_PLAN` + `DEFAULT_DISPATCH_CONFIG` —— §2.4.4 特征词表 / scene 候选矩阵 / 阈值（minLenZh 30、minLenEn 12、hitThreshold 2）。
- `resolveMode(input): ResolvedMode` —— **自动/手动唯一入口**。输入 `{ query, scene?, explicitMode?, config? }`，输出 `{ mode, secondary?, hitKeywords, reason, viaFallback? }`。逻辑：手动优先（用户指定 > 自动分流）；自动走候选集计分词（特征词≥2 或高置信单字 1 即命中）；多模式命中按优先级裁决主/次模式；critical 禁极简（16.5 硬规则）。
- `isManualMode()` / `modeWeights()` / `modeSpec()` —— 判别辅助与配置读取。

### 2.3 接入点（agent.ts 接线，下一步待确认后实施）

在 `agent.ts recall()` 顶部（约 64–72 行）用 `resolveMode` 替换现有手搓分支：

```ts
import { resolveMode, modeWeights, isManualMode } from './recallModes.ts';

const scene = req.scene ?? 'default';
// 手动必须指定具体模式：边界校验（API 入口做，未指定具体模式报 E_VECTOR/参数错误）
if (req.mode !== undefined && req.mode !== null && req.mode !== 'auto' && !isManualMode(req.mode)) {
  throw new MemAgentError('E_VECTOR', `非法的 mode：${req.mode}`);
}
const resolved = resolveMode({ query: req.query, scene, explicitMode: req.mode });
const minimal = resolved.mode === 'minimal';
// 后续候选/背景/打分全部改用 resolved.mode；17.8 打分透传 modeWeights(resolved.mode)
```

并补齐：
1. `selectRecallBackground` / `scoreMemory` 接入 `resolved.mode`：按 `selectPriority` 决定各层取用深度、按 `trimOrder` 决定超支裁剪顺序、按 `weights` 调整 17.8 四分量权重。
2. `RecallResult` 增加 `secondary_mode_hint?: {mode, content, note}` 与 `hit_keywords: string[]`（types.ts 已预留扩展位），`display` 块透明回显生效模式 + 命中词。
3. 审计 `action='mode_dispatch'`，detail 写 `{ mode, secondary_mode, hit_keywords, request_id }`（§4.3）。

### 2.6 落地进度（2026-11-13：A1 / A2 / A3 / A4 / A5 / A6 已上线）

- **A1（契约）**：`RecallResult` 增 `hit_keywords: string[]`（必填）与 `secondary_mode_hint`（显式 `null`）。锁法：`__tests__/recallContract.test.ts` 用 `@ts-expect-error` 构造缺字段对象——谁把字段改回可选，`typecheck` 立刻报 TS2578。
- **A2（分流观测）**：`agent.recall()` 顶部改调 `resolveMode`；非法 `mode` 抛 `MemAgentError`（不再静默当 auto）；每次项目召回写一条 `mode_dispatch` 审计，`detail` 同时记 **`mode`（分流结论）** 与 **`applied_mode`（实际执行）**。
- **两者为何会不同**：自动分流到「极简」在 A2 阶段**不执行**——极简会关掉项目背景与冷层补查，属 A4 分层取用范围；提前落地会让存量短查询召回静默变差。此场景 `mode='minimal'`、`applied_mode='auto'`，回显如实报 `auto`，不冒充分流已生效。
- **A3（权重透传）**：手动模式改用 `modeWeights(resolved.mode)`，字段**显式映射** `{f,i,c,a} → {w_f,w_i,w_c,w_a}`（直接展开会得 `undefined`）；`auto` 档继续用 `growth:v1`——默认档是绝大多数调用，不拿一次模式改动推翻自生长出的召回参数。审计 `mode_dispatch` 增 `weights_source`（`manual` / `growth:v1`）与 `weights`（实际生效向量），否则事后无法解释「为什么这条排第一」。
- **A3 的可观测效果**：同一候选集下 `fact_first`（c 权重 0.40）让高置信旧记忆胜出，`event_replay`（f 权重 0.40）让刚创建的低置信记忆胜出——排序真的翻转，不再是「传进=存下返回」。
- **A4（分层取用）**：手动模式带三张表生效——`disabledLayers` 在硬过滤层直接剔出候选（`minimal` 禁 L2/L5），且同一批层也不得作为「项目背景」回灌；`trimOrder` 接管超 3000t 的裁剪，从低价值层逐层丢（层内仍按 score 升序），`trimOrder` 未列出的 L1/L6 作兜底排最后；`selectPriority` 通过 trimOrder 的反向顺序体现（高排位层最后才被动）。auto 档仍走全局 score 升序裁剪。
- **A4 的可观测效果**：同一批数据下手动 `minimal` 只剩 L3、`fact_first` 超预算时 L5 被先裁而 L3 三条全保、auto 档 L5 照常保留（三组对照互斥）。
- **A5（次模式降级注入）**：`secondary_mode_hint` 仅在自动分流真的产出次模式时填写——在次模式 `selectPriority` 的首选层里挑一条**未被主命中选中**的记忆（否则等于把同一条记忆说两遍），按 `estTokens` 截断到 ≤200t（截断符也计入额度）。**只作独立 hint 下发，不并入 hits、不计入 payload**：偷偷塞进 payload 会让 3000t 硬熔断与省量口径同时失真，而 hint 的语义是「还能参考什么」，不是「已经注入了什么」。手动模式（即定论）与极简主模式（§2.4.3 无次模式）恒为 `null`。
- **A6（回显贯通 + 消除第三套口径）**：三段落地——
  1. **契约**：`RecallResult` 增 `dispatch: RecallDispatchInfo | null`（`source` / `suggested` / `applied` / `secondary` / `reason` / `weights_source`）。**只构造一次**，同时喂给返回体与 `mode_dispatch` 审计——两处各拼一份的后果是「回显说自动分流到事实优先、审计说手动指定」，事后无法判定谁对。会话视图没有分流动作，显式 `null`，不拿 `auto` 冒充「已分流到自动」。
  2. **回显**：`buildRecallModeLine()` 生成 `⚙ 模式：…` 一行（`⚙ 模式：事实优先（用户指定）` / `⚙ 模式：顶层洞察优先（自动分流 · 命中「架构」「选型」）` / `⚙ 模式：自动（分流建议极简轻量 · 本轮按默认口径执行）`），由 `echo.mode_line` 落地到 compact / markdown-full / html-details / 本机明细页四处，位置固定在「📊 汇总」之后、「▶ 明细」之前；`dispatch=null` 时不产出该行（不编一行）。模式中文名直接读 `RECALL_MODE_SPECS[mode].name`，不另立文案。
  3. **Web 侧**：检索页 `coreEngine` 删掉第三套分流词表 `autoDispatch`（`[{故障,核对,报错,发布,p0}→fact_first …]`，与内核 `MODE_FEATURE_WORDS` 完全是另一套），改为读内核 `dispatch` / `hit_keywords` / `secondary_mode_hint`；`history_query` **不再被降级成 default**（A1 已把该枚举补进内核 `Scene`，降级等于让这个场景在内核侧根本不存在）；原先写死的 `secondary_mode_hint: { mode:'minimal', note:'≤200t…' }`（只要不是 minimal 就编一条）改为读内核真值，无次模式即 `null`。
- **A6 的 UI 边界**：`ModeBanner` 只把「来源（自动分流 / 用户指定）」「命中关键词 chips」「次模式参考」按 `design/ui/检索页_原型.html` §2 原有版式呈现，**未新增行**——分流依据（`dispatch.reason`）留在审计里按 `request_id` 可查，不在横幅上再堆一行。
- **仍未生效**：`preload`（依赖会话态，本项目召回是无状态 MCP 调用，暂缓）；4 套模式尚无「专属分支逻辑」——目前差异全部由权重（A3）、分层取用/裁剪（A4）、次模式（A5）三段表达。
- **回退**：A2 的改动集中在 `agent.recall()` 顶部十余行，去掉 `resolveMode` 调用即回到手搓分支，不影响召回结果。

## 三、模式切换用户交互逻辑（默认=自动）

### 3.1 顶层控件

检索页 / MCP 工具参数 `mode` 统一呈现为**二元分段控件**：

```
[ 自动（默认） ]  [ 手动 ]
```

- 默认选中 **自动**。
- 选 **手动** 时，下方展开 5 个具体模式的选择器（顶层洞察优先 / 事实优先 / 事件复盘 / 模式推理 / 极简轻量）；**未选具体模式时点「检索」触发校验提示「手动模式需指定具体模式」**，不允许空提交。
- 选 **自动** 时，展示一行说明「由系统按场景与关键词自动判断模式」，不展示 5 选项。

### 3.2 场景联动

- `critical` 场景下，**极简**在手动选择器里**灰显禁用**（16.5 硬规则），hover 提示「合规/资金场景禁用极简」；即便用户曾把某项目默认设成极简，进入 critical 也强制降为事实优先（已在 `resolveMode` 兜底）。
- `history_query` 场景自动分流主推事件复盘，UI 可在自动档下显示「本次倾向：事件复盘」预览。

### 3.3 持久化与重置

- 用户在手动档选定某具体模式后，可「设为该项目默认」；但**全局默认恒为自动**，提供「重置为自动」一键回退。
- 会话级记忆：同一会话内连续手动选择可记忆到会话结束，跨会话不强制。

### 3.4 透明与反馈闭环

- 召回结果 `display` 块回显：**生效模式** + **命中关键词**（来自 `resolveMode.hitKeywords` + `reason`），让用户知道「系统替你选了 X，因为命中了这些词」。
- 结果页带「这次模式选对了吗？」👍/👎；👎原因选「召回内容不对」记入 7.2 自生长引擎的「分流错误样本」，每周重拟特征词权重（§2.4.4 工程约束 3）。
- 手动档下回显「用户指定：事实优先」，与自动档的「自动分流：…」区分，便于审计溯源。

### 3.5 MCP 客户端适配

- `recall_memory` 的 `mode` 参数说明已更新为自动/手动措辞（mcpSchema.ts:31）。
- 客户端注入的 `MCP_INSTRUCTIONS` 维持单份即可——具体模式的 System Prompt 差异由 `specs/召回模式SystemPrompt模板.md` 提供，自动档下 Agent 按 `resolved.mode` 在内部套用对应模板约束（详见该文档「auto 如何选用模板」）。
