### 决策 ② `manage_memory(delete)` 默认开放？（**已按契约实现：默认不开放**）
契约 §4 明确「delete 建议默认不开放，配置开关 `MCP_ALLOW_DELETE=1` 才暴露」，
且工具描述要求引导 Agent 优先 `forget` / `archive`。**D5-2 已按不开放实现**：
两端 `allowDelete` 缺省读环境变量 `MCP_ALLOW_DELETE`（仅 `'1'` 放行），也可在启动参数显式注入；
开关未启用时 `delete` 回明确错误（引导 `forget`/`archive`），启用后才放行并写审计、落墓碑。
工具描述与 `MCP_INSTRUCTIONS` 第 7 条同步写了「除非用户明确要求删除，否则优先 forget/archive」。

### 决策 ③ `gc_report` 报告字段口径（**已按诚实原则实现**）
契约 §7 示例字段 `{freshness_updated, migrated, summaries_created, summaries_filtered,
merged_originals, compressed}` 是**目标系统的遗忘引擎报告**，本项目内核只有
`{decayed, merged, conflicts_resolved, request_id, audit}`。
按项目红线「不伪造统计」：**D5-3 已如实返回内核真实三项 + `note` 附注差异**，未把 `decayed`
改名冒充 `freshness_updated`，也未补 `summaries_created: 0` 假装统计过。

`resolve_conflicts`，传入即明确拒绝（不静默忽略）。

## 5. 横切约束（所有子任务共用，逐条钉测试）

1. **令牌作用域**：所有读/写/管工具统一 `projectInScope(account.scope_project_ids, project_id)`；
   多工具按 `mem_id` 操作时，先 `getMemory` 取 `project_id` 再校验，越界即拒。
2. **租户闭包**：`user_id` 不得由客户端冒用（沿用 `write_memory`/`get_preferences` 既有校验）。
3. **L0 不泄**：任何返回都不得带 `content_l0_enc`、`content_orig`、`has_l0` 之外的密钥材料；
   `list_memories` 的 `snippet` 只取 `content_l1`/`content` 前 200 字。
4. **诚实降级**：找不到 → `ok:false` + 明确原因，不补造空记录；不支持的统计量不伪装成 0。
5. **两端一致**：TCP(8202) 与 HTTP(8204) 行为、错误文案、返回形态必须一致；每个工具都要有两端用例。
6. **不碰遗留**：工作树长期存在的早期未提交改动（`errors.ts`/`memories.ts`/`main.ts`/
   `L0WriteUnlock.tsx` 等）严格排除；`memories.ts` 若必须改（D5-3/4），用 hunk 级拆分暂存。
7. **索引**：源码行数/哈希变化后，按「已提交源码」非破坏式重生成
   （备份→临时还原→`code:index -- --write`→校验→原样恢复），保证 CI 干净检出通过。
8. **门禁**：`vitest run --maxWorkers=1`（全量，避免已知并行 flaky）、`npm run typecheck`、
   受影响文件 `oxlint`、干净树 `code:index:check`。
