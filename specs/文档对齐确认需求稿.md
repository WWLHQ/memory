## 4. 回显档位格式偏好（M1，专项修正）

> 用户指令："回显档位，尽量用两行摘要折叠气泡可展开的格式，HTML 格式兜底的方式实现。"
> 修订（批次43 二次校正）：**取消 markdown-full / 单行 作为最弱兜底**；**所有回显参数必须对 APP 内同名参数对齐，实现互通**。

### 4.1 档位（仅两档，取消最弱兜底）
- **首选（compact 档）**：两行 🧠 Memory 摘要 + **可展开折叠气泡**——气泡内联展开显示四段明细（项目背景 / 命中记忆 / Token 用量 / 省钱与费用），点击收起。
- **兜底（fallback）**：客户端不支持气泡折叠时，回退 **HTML `<details>`** 四段（summary = 🧠 Memory 提示行，内层四段）。即原 `html-details` 档并入「HTML 兜底」。

> 不再保留 markdown-full / 单行兜底。无法渲染气泡与 HTML 的极端客户端，按 fail-safe 处理（占位/提示，不编造明细），其具体形态由 APP 内参数定义。

### 4.2 互通约束（参数对齐 APP）
- 回显相关的**全部参数**（档位名称、触发阈值、客户端能力判定键、四段明细字段、`detail_url` 形态、折叠/展开文案）必须**与 APP 桌面端内部参数对齐**，取自同一真源，不得各写一套：
  - 服务端：`src/core/memagent/mcpRecall.ts` 的 `recallDisplayMode` / `clientSupportsHtmlDetails`；`recallInsight.ts` 的 `buildRecallCompactMarkdown` / `buildRecallDetailPage`。
  - 渲染端：桌面/Web 渲染层消费 `display.mode` 的组件。
- **互通判定**：Agent 侧下发的 `display.mode` 与 APP 渲染端消费的 mode 必须一致；新增/修改任一档位参数须同步两侧，避免「Agent 回显与 APP 渲染口径分裂」。
- **影响文件**：本项目 `接入Agent行为规范.md` §3 改写（与 `mcpRecall.ts`/`recallInsight.ts` 对齐）；目标 SOP §9.4（R1）同步此两档表述 + 互通说明。
