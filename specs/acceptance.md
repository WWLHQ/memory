# 验收标准（多 Agent 记忆助手）

> 每条 AC 对应一条 REQ；结构化首版，细节以对应需求规格书为准。

## AC-001 产品定位明确
对应 REQ-001：产品定位、目标用户、核心价值有书面定义并被评审通过。

## AC-002 租户隔离可用
对应 REQ-002：切换租户后全局上下文与数据按租户隔离，无串档。

## AC-003 Agent 接入可配置（字段级）
对应 REQ-003：可为每家 Agent 创建接入卡片并保存字段，校验生效。字段级验收（来源：需求规格书_Agent接入页字段级交互规格.md §0~§9 / §8 验收用例）：
- AC-003.1 卡片头：agent_name 受枚举约束；enterprise_id/team_id 只读（R1 租户禁手填）；连通成功率<95% 告警、平均延迟>5s 告警、熔断状态点 CLOSED/OPEN/HALF_OPEN
- AC-003.2 单 Agent 操作：测试/轮换/吊销 触发对应行为与审计文案（「已轮换，旧 Key 24h 内有效」/「已吊销该 Agent 密钥」）
- AC-003.3 状态机：ONBOARD→CONFIGURED→CONNECTED；测试失败/熔断 OPEN→DEGRADED（§0/R5/R6）
- AC-003.4 一键全量接入：四段进度条跑通、自动打标 P0/P1/P2、默认只读召回（R8）、可撤销（R9）、限本机（R10）
- AC-003.5 MCP 工具：recall_memory/write_memory 必带 project_id（R2）；scene=critical 禁 minimal（R3）；category 枚举（17.6）
- AC-003.6 双通道：主+补偿至少开一（R4）；主通道熔断自动降级仅补偿（R5）；SHA-256 幂等不可关
- AC-003.7 密钥：界面恒脱敏、不回显明文（R5/R6）；轮换 24h 宽限；超 90 天黄色提醒
- AC-003.8 测试面板：发 recall 显示注入预览 + request_id（R7）；熔断 OPEN 禁用测试
- AC-003.9 校验规则：R1–R6 前端落地；R1–R10 统一校验函数可复用
- AC-003.10 按端置灰：form 徽标（19.10）；信号源按端置灰；auto_bind 审计记 form（19.11）

## AC-013 召回质量增强可用
对应 REQ-013：时间窗解析与加权、幂等写入、标识符加权、source 标记过滤、真实状态驱动 UI 五项能力按规格落地，且互不破坏现有架构（召回模式单一真源、回显铁律、纯本地零出网）。
- A1 `src/shared/timeWindow.ts` 纯函数解析相对时间（昨天下午 / 3 天前 / 7am / 今天早上）产出本地时区时间戳与 `query_timestamp`，单测覆盖东八区边界（早上 7 点不落到前一天）。
- A2 `agent.ts` 打分接入时间窗修正项，命中时间窗的记忆加权；`recallModes.ts` 档位数与 `resolveMode` 行为不变（反向断言）。
- A3 `pendingWrites` / `sessionCollector` 内容级 sha1 去重 + 游标不推进；同内容重发幂等、断点续传，且与「pending ≠ 成功」语义共存。
- A4 `vector` / `forgetting` 标识符精确词加权生效（标识符权重 3），词袋检索命中率提升可量化。
- A5 采集侧对注入标记 / `plugin` 来源 / `<memory-context>` 三处过滤；真实状态轮询把 409 视为「排队中」而非失败。
- A6 后台操作状态来自**多来源真实审计只读派生**（`sync_*` / `schedule_run` / `memory_op` / `graft` / `gc` / `auto_bind`），按 `request_id` 取最新一条、时间倒序展示；**不新增任何审计写入**；无相关审计 → 整块不渲染（诚实空态，不显示全 0 假卡）。

## AC-014 P1 客户端整形改造可用
对应 REQ-014：回拼原文与新旧覆盖、保真声明强化、侧栏真实状态卡三项能力按规格落地，且互不破坏现有架构（召回模式单一真源、回显铁律、纯本地零出网、L0 密文不进）。
- A1 `recallSupersede.ts` 纯函数：用**影子向量探测**（`sim ≥ 0.85`）反查 `merged_into` 目标并把最新版补进 hits，打 `superseded` 标记，不重复带入；目标已在命中时只打标不改正文；无影子命中时行为不变（守恒断言）。单测覆盖探测 + 去重 + 守恒。
- A2 命中卡（明细页 + RAG 四段标注行尾）对 `superseded` 项加中性标注「以最新版为准」，只加标注不改写正文（`display.markdown` 逐字不变，反向断言）。
- A3 `source_excerpt` 可选字段（≤200 字、L0 密文不进）：写入侧填充，召回拼装时摘要+原文片段双保真（同文不重复）；单测覆盖填充、脱敏与拼装一致性。
- A4 明细页 footer（`recallInsight.ts` 的 `buildRecallDetailHtml`）保真声明强化（数字同源 / 以最新为准 / 不含令牌 / 不编造）；不进 `display.markdown`、不进注入头；`display.markdown` 逐字不变（反向断言）。
- A5 侧栏状态卡经 `hostCall` 拉取**真实可读**通道——`collector:status` / `l0:pendingWrites` / `refine:state`——轻量轮询（`SHELL_STATUS_POLL_MS = 12_000`，落在 10–15s）展示；`navStatusChannel.ts` 一次性回传状态摘要，与 `navCountChannel` 角标互不覆盖；读不到/失败/未知**不产出条目**（不拿 0 或「空闲」冒充）。**同步面例外并如实声明**：`sync:*` 全为主动触发/需会话的通道（`push`/`pull`/`reconcile`/`conflicts`…），**没有**被动读「是否在同步 / 上次是否失败」的通道，故状态卡**不展示**同步状态（`NavStatusSource.sync` 只作契约预留，未接源即不产出条目）。明确不实现长轮询与一键部署向导。
