# 人工测试清单（当前版本 · 2026-10-31）

> 本文件是**通用手测入口**；每个修复批次的详细用例与结论见 `MANUAL-TEST-FIX-BATCH-1..23.md`。
> 历史文档 `MANUAL-TEST-PHASE-A..E.md`、`MANUAL-TEST-BATCH.md` 保留作归档，命令/账号可能已过时。

## 1. 启动与环境

| 方式 | 操作 | 说明 |
| --- | --- | --- |
| 正式安装包 | 运行 `release/installer/MultiAgent Memory-0.1.0-setup.exe` | 安装后从开始菜单启动 |
| 便携/未打包 | `npm run package:win` 后运行 `release/win-unpacked/MultiAgent Memory.exe`（`npm run package` 成功后该目录会被清理） | 与安装包同一套主进程 |
| 开发态 | `npm run build:electron` + 启动 Electron（或直接跑打包产物） | 批次23 起 `npm run dev` 会**自动拉起本机登录后端（8201）+ Vite（固定 `127.0.0.1:5180`）**，浏览器登录开箱可用；8201 已有兼容后端时复用。若 8201 被安装版桌面端占用（来源不允许 5180），脚本会提示先关闭桌面端。仅需后端时可单独 `npm run dev:backend` |

- 本机服务固定端口：agentOnboard **8200**、home/mirror **8201**、MCP TCP **8202**、Webhook **8203**、MCP HTTP **8204**；页面静态服务由系统分配随机端口。
- 数据目录：开发态/便携/安装包统一为 `%APPDATA%\MultiAgent Memory`（`memories.db.json`、`main.log`、`mcp-token.txt` 等）。
  旧开发态目录 `%APPDATA%\multi-agent-memory` **不会自动迁移**，如需保留历史数据请手工拷贝。
- 端口被占用时应用会弹启动失败对话框并退出（日志见 `main.log`），先关闭占用进程再启动。

## 2. 账号与登录（无演示账号）

1. 启动后进入「首页」，未登录显示登录门控；点「▶ 登录」。
2. 点「注册」，输入手机号/邮箱、≥6 位密码、确认密码与页面验证码 → 「注册」。
3. 用刚注册的账号登录。
4. **内置管理员（批次7）**：登录框提示 `admin` / `Admin@123456`；用该账号登录后顶栏显示「（管理员）」。
5. **预期**：
   - 顶栏显示账号与团队（团队由服务端分配，只读）；
   - 登出后回到门控态，再次登录正常。

> 账号/锁定表落数据根；连续输错会触发锁定（错 5 次锁 15min）。管理员首次登录后请立即在「安全」页修改默认密码（已有管理员密码不会被再次播种覆盖）。

## 2.1 管理员权限（批次7）

1. 用普通注册账号登录「安全」页：密码策略控件禁用并提示「需管理员」；数据根更改/恢复、备份操作同样禁用并显示「需管理员权限」。
2. 用 `admin` 登录「安全」页：
   - 「管理员账号」卡片列出全部账号（admin 在最前），可切换角色、修改团队、修改自己的密码；
   - 把唯一管理员降级为普通成员 → 应报「不能降级最后一个管理员」；
   - 密码策略可修改，变更写入 `security_change` 审计并回执 `req_`。
3. 用管理员在「参数」页更改数据根/备份：应正常执行；用普通成员操作同一按钮：应被禁用/拒绝（主进程与后端双重校验）。
4. 在管理员卡片把某成员提升为管理员 → 该成员重新登录后顶栏也显示「（管理员）」。

## 2.2 动作日志（批次7，排查第一入口）

1. 打开「参数 → 数据存放位置」卡片，确认「动作日志」路径指向数据根下 `actions.log`。
2. 做任意操作（点按钮、登录、改策略、备份），然后用文本编辑器打开 `actions.log`。
3. **预期**：
   - 每行格式 `[ISO 时间] [level] [scope:action] [requestId] {json}`；
   - 能看到 `ui:click` / `ui:submit` / `home:login` / `ipc:*` / `home:http` 等动作；
   - 密码、令牌、密钥字段显示 `***`，不出现明文；
   - 出错时能看到 `[error]` 行与 `error` 字段；`main.log` 只保留启动/迁移类诊断。
4. 日志超过 5 MiB 时自动轮转为 `actions.log.1 … .3`（最多 3 份历史）。


## 3. 首页真实数据（不得出现示例/假文案）

1. 登录后看四卡：累计记忆 / 累计动作 / 近 1h 调用 / 待裁决。
2. 通过 MCP 或 Webhook 写入一条记忆，再回到首页刷新。
3. **预期**：
   - 累计记忆与累计动作随真实账本 +1；近 1h 调用按审计时间计算；待裁决为含 `conflict_id` 的记忆数；
   - 四卡来源标注「内核账本·实时」；
   - 若存在 `evidence_thin` 等异常，异常区出现蓝色 `.rid`，点击弹出「溯源审计」并显示真实 `request_id`；
   - 账本为空时显示 0/空态，不出现「-58%」「3.2×」等示例数字。

## 3.1 L1–L6 关系图谱（批次 8 新增）

1. 登录后首页四卡下方应出现「L1–L6 关系图谱」卡片（深色画布 + 六个层中心 + 中央「记忆账本」核）。
2. **空账本**：若账本无记忆，画布只显示六层 hub 与中央核，并显示「内核账本暂无记忆 · 无演示节点」（不得出现任何示例节点/边）。
3. **有数据**：先用「写入」页或 MCP/Webhook 写入 2–3 条记忆，回到首页点图谱右上「刷新」：
   - 记忆节点按 `category` 着色，边连到其有内容的层 hub；有 `merged_from/merged_into` 时出现合并边，有 `conflict_id` 时同冲突组出现冲突边；
   - 点层 chip（L1–L6）只高亮该层记忆，再点「全部」恢复；点层 hub 也有同样筛选效果。
4. **搜索**：输入关键词，只保留命中节点并高亮其邻居；无命中显示「无匹配记忆」；冷/休眠/归档记忆不可按原文搜到（G3）。
5. **缩放/平移**：`Ctrl/⌘ + 滚轮` 或 +/− 按钮缩放（55%–240%），拖拽画布平移，双击或「复位」回到 100%。
6. **详情抽屉**：点任意节点，右侧抽屉显示分类/层/衰减、L1–L6 各层内容与 `mem_id`；冷/休眠/归档节点只显示「仅 L2 占位符，展开原文需审计」及尾号，**不得**出现原文。
7. **刷新与日志**：点「刷新」后状态同步；在 `actions.log` 中应能 grep 到 `[home:graph_zoom]`、`[home:graph_filter_layer]`、`[home:graph_node_open]`、`[home:graph_search]`（只含 `query_len`/`hits`，不含搜索原文）、`[home:graph_refresh]`。

## 3.2 L0 加密授权查阅（批次 9 新增，完整用例见 `specs/MANUAL-TEST-FIX-BATCH-9.md`）

1. **管理员初始化**：`admin` 登录 → 账号与安全 → 「🔐 L0 密钥环」→ 首次设置管理密码（≥8 位，两次一致）→ 显示「管理密码：已设置 / 写密钥：已解锁」；`l0-keyring.json` 只有 wrapped DEK，无密码/DEK 明文。
2. **写密钥分离**：安全页「锁定写密钥」后到写入页提交 → 返回 `E_L0_LOCKED`，无回执、不落明文；解锁写密钥后可正常写入；`memories.db.json` 新记忆只有 `content_l0_enc`（v2 信封），无 `content_orig`，grep 原文无命中。
3. **L0 不参与检索**：在检索页搜索 L0 原文中的 URL/密钥/手机号 → 不命中；L1 为脱敏占位符。
4. **逐层查重/嫁接**：连续写入两条高度相似内容 → 第二条回执动作 `graft`，`graft_to/graft_layer` 指向第一条；第一条 L1 文本不变、`grafted_from` +1；首页图谱出现橙色点线嫁接边与「嫁接」图例/统计。
5. **成员一次性授权**：成员在日志/记忆页提交查阅申请 → 管理员安全页「批准」并拿到一次性密码 + `grant_id` → 成员用两者解锁可看 L0；同一 grant 再次解锁报「已过期/已使用」；换账号使用报「不属于当前账号」。
6. **连续会话**：解锁后倒计时 5 分钟；保持页面可见+聚焦时每 60s 心跳续期；切走/最小化 >5 分钟自动锁定并作废 grant（审计 `l0_auth_expire`）；「立即锁定」、锁屏、休眠、重启应用同样锁定并作废授权。
7. **错误锁定**：连续 5 次密码错误 → 锁定 15 分钟 + 该 grant 作废（`home-locks.json` 的 `l0:<user_id>`）；审计 `l0_auth_fail` 不含密码。
8. **旧数据迁移**：解锁写密钥后点「迁移旧数据」→ 显示扫描/迁移/待处理报告与 `backups/l0-migrate-<ts>/` 备份；旧 `content_orig` 清空、v1 信封重加密为 v2。
9. **访问控制**：未登录/普通成员打开安全页只看到「需管理员权限」，无设置/写密钥/发放控件；L0 查阅输入框仅在登录后出现。

## 3.3 噪声过滤与脱敏补齐（批次 10 新增，完整用例见 `specs/MANUAL-TEST-FIX-BATCH-10.md`）

1. **寒暄/身份询问被过滤**：写入「你好」「你好，有什么可以帮您的吗」「你是谁 / 你是什么模型 / 你能做什么」→ 回执为过滤（`filtered`），账本不新增条目。
2. **助手自述被过滤**：写入「你好，我是 DeepSeek，我可以帮你写代码、分析数据、回答问题。」→ 过滤；但「你好，部署前请检查 nginx upstream 超时配置」必须**正常入库**（含实质证据不误杀）。
3. **脱敏补齐**：写入含 `10.0.0.9`、`192.168.1.20:8080`、`2001:db8::1`、18 位身份证号、`ftp://`/`ssh://`/`ldap://` 地址、`Authorization: Basic …`、`Cookie: …` 的内容 → L1 只出现 `[IP]`、`[证件号]`、`[服务地址]`、`[API_KEY]`；`v1.2.3.4` 等版本号保持不变。
4. **手动编辑过门**：记忆页打开一条真实记忆，把内容改为纯噪声（如「你好，我是一个 AI 助手」）→ 保存被拒绝并提示「质量门」，账本内容/版本不变，审计出现 `memory_op` + `filtered_l0_to_l1`（`source=manual_edit`）；改成含 PII 的技术内容 → 保存成功且 L1 已脱敏、L0 密文不动。
5. **自动摘要过门**：构造 3 条同项目、同类别、内容纯噪声的相似记忆，触发遗忘周期（或单测 `runForgettingCycle`）→ 不生成摘要，原文保持 hot/warm 不变，`gc` 审计 `summaries_filtered ≥ 1` 且 `summary_filter_reasons` 记录「质量门」。

## 3.4 MCP 客户端接入推广（批次 15 新增，完整用例见 `specs/MANUAL-TEST-FIX-BATCH-15.md`）

1. 用**管理员**登录 → 「Agent 接入配置页」→「MCP 客户端接入状态」：
   - Qoder CN 已配置并带令牌 → `已接入`；
   - `~/.claude.json` 有 `memagent` 条目但无 `headers.Authorization` → `缺令牌（调用会 401）`；
   - Codex（`~/.codex/config.toml`）无本服务条目 → `未配置本服务`；Trae CN / WorkBuddy / Zcode / deepseek harness → `需手工添加`。
2. 点 Claude Code 行「补齐令牌」→ 提示已写入且显示备份路径（`~/.claude.json.bak-<时间戳>`）；再次点「刷新状态」→ 变为 `已接入`；再点一次「补齐令牌」应显示「已是最新，未改动」。
3. 点「复制片段」→ 片段含 `Authorization: Bearer …`，可粘贴到其它客户端；**令牌不得出现在** `actions.log`/`main.log`。
4. 用**普通成员**登录 → 复制/写入按钮禁用并提示「需管理员」；后端直接伪造 sessionId 调 IPC 也应被拒绝。
5. 重启 Claude Code，在工作区提问仓库实现/踩坑类问题 → 应出现「🧠 Memory 提示行 + 四段折叠」；随后在数据根 `memories.db.json` 的 `recall` 审计里核对 `detail.client` 含 `Claude`（未识别时可能为空，不得伪造）。
6. 冲突保护：手工把某 JSON 客户端的同名条目改成其它端点 → 面板显示 `冲突` 且「一键接入」禁用；不会覆盖原条目。

## 3.5 登录即自动接入 + 卡片真实指标（批次 16 新增，完整用例见 `specs/MANUAL-TEST-FIX-BATCH-16.md`）

1. **登录触发**：用管理员登录 → 不打开接入页，等 3–10 秒（安装痕迹扫描需读注册表/文件）→ 打开「Agent 接入配置页」：
   - 顶部显示「✅ 已自动接入 · 切页/重载保持」与「↻ 撤销并重接」；
   - `scanState` 为「完成 · 发现并绑定 N 个 · 宿主真扫」；`#found` 每行带真实信号（进程/安装痕迹/配置）与「宿主真扫」；
   - 本机确有安装的 Agent 自动出现在 `#cards`（未内置演示卡）。
2. **MCP 自动写入**：登录会话为管理员且 Agent 已连通时，页面出现「🧠 MCP 接入（自动写入已连通 Agent）」摘要；到 `~/.claude.json` / `~/.qoder-cn/settings.json` 核对：
   - 本服务条目含正确端点 `http://127.0.0.1:8204/mcp` 与 `headers.Authorization`；
   - 写入前生成 `.bak-<时间戳>` 备份；Codex（TOML）/无稳定路径客户端显示「需手工添加」；
   - `actions.log` 出现 `[mcp:client-wire]`，不含令牌。
3. **卡片指标首刷**：打开接入页即检查每家卡片四项指标，不得全为「—」（有真实审计时）：
   - 连通成功率 = `/audit` 中该 Agent `test` + `auto_bind` 通过数 / 总数；
   - 熔断状态 = `/agents` 的 `circuit`（OPEN 时「测试接入」禁用并显示熔断降级）；
   - 平均延迟 = 审计 `durationMs` 均值（无样本显示「—」，不估算）；
   - 租户 = 当前登录 `enterprise_id / team_id`（只读）。
4. **异常提示 + 手动检测**：停掉接入后端（结束 8200 端口进程）后重新登录或点「撤销并重接」→ 页面显示「⚠ 自动接入未完成：…」且提示点「🔍 手动检测」；点击后仍如实显示失败原因，不伪造卡片/连通。
5. **成员边界**：用普通成员登录 → 自动扫描照常，但 MCP 自动写入摘要显示「需管理员权限才能写入 MCP 配置」，配置文件不被修改。
6. **浏览器模式（`npm run dev`）**：点「⚡ 自动发现并接入本机 Agent」→ 四段进度后显示「自动接入失败 · 非桌面壳环境…」，提示改用桌面应用或手动检测；不得出现「内核模拟」发现行或伪造卡片。

## 3.6 程序运行日志窗口（日志记录页，批次17 建 / 批次19 迁移）+ 打包清理（完整用例见 `specs/MANUAL-TEST-FIX-BATCH-17.md` / `-19.md`）

1. **桌面应用（安装包，或 `npm run package:win` 生成的便携目录）**：打开「日志记录页」，标题下方应看到「🖥 程序运行日志」卡片：
   - 默认显示最近 **5 行**真实 `actions.log`（格式 `[时间] [info/warn/error] [scope:action] [rid] {json}`），时间为 UTC+08:00；
   - 底部显示日志文件真实路径；点「↻ 刷新」立即重读；每 5 秒自动更新，切到其它页/最小化时暂停轮询；
   - 新产生的操作（点按钮、登录）应在数秒内出现在列表中。
2. **错误反馈**：制造至少一条 `[error]`（例如停掉 8200 后端后点一次自动接入；或直接向 `actions.log` 追加一行 error 测试），回到日志记录页 → 出现「⚠ 最近 20 条程序日志中有 N 条错误。请复制诊断信息反馈给维护者。」
   - 点「📋 复制诊断信息」→ 剪贴板包含时间(+08:00)、页面路径、日志文件路径与原始日志行；
   - `actions.log` 出现 `[ui:program_log_copy]`，**不含**日志正文。
3. **不刷屏**：让日志记录页停留 ≥1 分钟，`actions.log` 不应出现 `ipc:log:tail` / `host:log:tail` 记录（尾读为静默通道）。
4. **位置校验**：回首页确认**不再**出现「🖥 程序运行日志」卡片（批次19 起只保留在日志记录页）。
5. **浏览器模式（`npm run dev`）**：日志记录页的日志卡片显示「当前为非桌面壳环境，无法读取程序日志」，**不得**出现任何日志行或错误提示。
6. **打包清理**：
   - 打包前记录 `release/` 下 `installer-*` 目录数量（历史产物），以及是否存在旧便携包 `release/win-unpacked` / `release/builder`；
   - 执行 `npm run package` 成功后再看 `release/`：只保留本次 `installer`（或本次时间戳目录），旧 `installer-*`、旧便携包 `win-unpacked` 与 `builder` 残留均被删除（批次18）；
   - **批次19 起**：打包开始时若检测到本仓库 `release/` 下有运行中的旧实例，日志先打印「强制结束旧实例 PID …」并结束进程，再重命名旧目录；
   - 打包开始时旧 `release/installer` 先被重命名为 `installer-<UTC 时间戳>-stale`，成功后删除；日志有「旧安装包目录清理 N 个」与「已删除旧便携包/残留」；
   - 若强制结束后 `installer` 仍被占用（重命名 3 次仍失败），本次先落到 `installer-<时间戳>`；**构建成功后脚本会重试删除旧 `release/installer` 并把产物移回固定路径**（日志「已删除旧 release/installer，并把本次产物收口到固定目录」）；仍失败才保留原目录与时间戳产物；

   - 需要完全关闭调度时 `MAM_FORGETTING_DISABLED=1`（日志出现 `forgetting:scheduler-disabled`）。
6. **预期（聚类安全）**：不同项目/团队/租户的相似内容**不会**被合成同一摘要；`fact/context` 与 `preference（cautious）` 类别不自动合并。

> 参数页「知识库策略表」的半衰期/归档/合并数值当前只保存为偏好记忆，尚未被调度消费；页面已标注该限制。

## 8. 已知限制（不应作为缺陷）

- 本版本不提供云端同步；`wired:false` 与「同步未实现（本版本不提供云端同步）」是预期展示。
- 首次启动/更换数据位置后应用会自动重启一次（让 Chromium 缓存与全部数据落到新目录），属预期行为。
- 数据根指针固定为 `%APPDATA%\MultiAgent Memory\data-root.json`；删除/损坏该文件会重新进入选择流程。
- 旧版 P8「记忆库保存位置（dbDir）」设置已退役；旧库在首次启动时经迁移向导一次性导入。
- 真实 LLM Provider 未装配，L2–L6 仅在接入 Provider 后生成；当前写审计 `refined_by=stub`。
- **纯浏览器模式（`npm run dev`）无法写入**：没有 Electron 主进程的 L0 写密钥，写入一律 `E_L0_LOCKED`；L0 查阅输入框未登录时不显示。
- **L0 一次性授权**：解锁即消费并删除 wrapped DEK；5 分钟中断/锁屏/休眠/重启即作废，再次查阅需重新申请。
- **管理密码不可找回**：DEK 无后门；丢失管理密码与全部授权后只能删除 `l0-keyring.json` 重新初始化（历史 L0 密文永久不可解，L1–L6 不受影响）。
- 旧账本的明文 `content_orig` 需管理员在安全页执行「迁移旧数据」（迁移前自动备份）；未迁移条目的 L0 查阅为空。
- 参数页知识库逐行策略未接入执行。
- `release/installer` 目录可能被本机索引器/运行中程序占用；批次19 起打包前先强制结束本仓库 `release/` 下的旧实例，重命名带 3 次重试，仍占用则先输出时间戳目录、构建成功后自动收口回 `release/installer`（仍失败才保留时间戳目录并告警）。批次17 起打包成功后会清理旧的 `installer-*` 目录，批次18 起同时清理旧便携包 `release/win-unpacked` 与 `release/builder` 残留；被占用的目录删除失败只告警（需先关闭占用程序）。
- 日志记录页的程序日志窗口只读 `actions.log`（含已轮转分片）最近 **50** 条，固定高度可上下滚动，默认人话视图（批次24）；不含内核审计与 `main.log`；浏览器模式不可用属预期。批次19 起该窗口只出现在日志记录页，首页不再显示。
- 遗留账本清理（批次24）只降级「能被证明是 stub 精炼器产物」的历史行，判定不做语义猜测；执行不可逆，只能从执行前的自动备份恢复；纯浏览器模式无主进程 IPC，卡片如实显示不可用。
- 层级生成时间（批次24 口径2）一条记忆只记一个时刻，不逐层记；批次24 之前的历史行显示「层级生成未记录」，不用入库时间冒充。
- 日志/审计列表列宽按**列序号**保存在 localStorage（批次24）：将来表格增删列需要点「恢复默认」重新对齐；jsdom 无真实布局，拖宽只有单测覆盖，视觉效果需手动验收。
- 开发态端口回退（批次24）只解决登录/镜像服务的来源受信问题；接入服务（8200）若同样被安装版桌面端占用仍会拒绝 5180 来源，浏览器模式仍无宿主能力（MCP 客户端扫描、数据根 IPC、L0 写密钥）。
- `release/win-unpacked` 等目录中大量 DLL/PAK 显示 `1980/1/1 8:00` 是 Electron 官方分发包的 ZIP 时间戳（DOS 时间起点），不是构建时间；新生成的 `resources/app.asar`、安装包与被 rcedit 改写的 exe 才是本次构建时间。该便携目录仅由 `npm run package:win` 生成，并会在下一次 `npm run package` 成功后被清理。
