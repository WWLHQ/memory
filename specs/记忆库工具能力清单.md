# 记忆库工具能力清单（读 / 写 / 管理）

> 文档目的：按「读 / 写 / 管理」标准能力，盘点记忆库（MultiAgent Memory）预期对外工具与必备内部 / 外部组件。
> 本文为**能力盘点**，不涉及服务启停、不含实现代码。
> 状态说明：`✅ 现有` = 已落地（MCP 或内核 API）；`🔲 缺口` = 预期但未实现（部分底层已具备，标注"底层已有"）；`🟡 未接线` = 引擎已实现但未接入内核 API。
>
> **〔批次43 对齐校正〕**：本文与 WorkBuddy 工作集 `multiagent-memory-ops` 对齐，**严格区分「Agent 面 MCP 工具」与「运维/管理端能力」两类计数口径**。Agent 面 = 12 个（读7 / 写2 / 管3）；运维/管理端能力（logs/overview/discover/sync/L0 授权族等）**单列不计入 Agent 工具数**。旧版把运维能力混进 Agent 面导致「≈17」的口径作废。

---

## 1. 出发点：记忆库的特性决定工具形态

本记忆库不是普通 CRUD 库，以下特性贯穿全部工具设计：

- **L0→L6 分层**：原始归档（L0 加密）→ 精炼产物（L1–L6），所以"写"只落 L0，"读"主要消费精炼层。
- **多租户三池 + 令牌作用域**：私人池 `P-<user>` 与共享池 `P-shared`、归档池 `P-archive`，所有读 / 管都受 `projectInScope` 约束（详见 `多用户三池隔离设计_D1-D25.md`）。
- **共享前必脱敏**：`P-shared` 只收脱敏后的 L1，脱敏闸门跑在内核。
- **衰减与遗忘**：记忆有半衰期 / decay，需要 GC 而非永久留存。
- **全量审计 + L0 保险库**：每次动作留痕，L0 原文受管理员密码与会话授权保护。

## 2. Agent 面 MCP 工具（12 个，读 7 / 写 2 / 管 3）

> 口径定义：**Agent 在会话内可直接调用的 MCP 工具**。运维/管理端能力见 §3（单列，不计入此数）。
> 命名对齐 MCP 工具名（`recall_memory` / `manage_memory`）；内核 API 同名概念见 `需求规格书_内核API契约.md`（如 `ma.recall` / `ma.browse`）。

### 2.1 读（Read）— 取回与查询（7）

| 工具 | 作用 | 为何归"读" | 现状 |
|---|---|---|---|
| `recall_memory` 语义召回 | 关键词 / 向量召回精炼记忆，带回项目背景、省量、费用 | 主查询入口 | ✅ 现有（MCP）|
| `recall_memory(scope='session')` 工作记忆 | 按 `session_id` + 时间窗取"刚说了啥"，不走向量 | 会话级回溯，非语义 | 🔲 草案§6（recall 变体）|
| `list_projects` 列项目 | 列出令牌可见的项目 / 池 | 作用域导航 | ✅ 现有（MCP）|
| `list_memories` 列记忆 | 按 `category` / `decay_class` / `source_agent` / `tag` / 时间过滤 + 分页 | 浏览 / 审计用 | ✅ 现有（MCP，批次44-D5-1；TCP/HTTP 共用 `mcpReadTools.ts`）|
| `get_memory(id)` 单条精确读 | 按 `mem_id` 取一条 | 精确读取，补语义召回盲区 | ✅ 现有（MCP，批次44-D5-1；不存在如实回 `ok:false`）|
| `get_preferences` 取偏好 | 跨 Agent 用户偏好 | 轻量配置读 | ✅ 现有（MCP）|
| `get_write_status` 探锁 | 读 L0 写密钥解锁态 + pending 待重放条数 | 写前探活；解锁态顺带重放 | ✅ 现有（MCP，批次44-D4；`L0Port.isWriteUnlocked()`）|

### 2.2 写（Write）— 产生与标注（2）

| 工具 | 作用 | 为何归"写" | 现状 |
|---|---|---|---|
| `write_memory` 写入 | 只落 L0 全量归档，绝不直写池；扩展入参 `importance`/`confidence`/`half_life_days`/`tags` | 唯一产生原始数据的入口 | ✅ 现有（MCP）+ 草案§2 |
| `feedback` 反馈 | confirm / reject / disputed，反哺置信度与强化计数 | 标注而非新建 | 🔲 缺口（底层 `_feedback` 已有）|

### 2.3 管理（Manage）— 治理与运维（3）

| 工具 | 作用 | 为何归"管" | 现状 |
|---|---|---|---|
| `manage_memory` 单条变更 | pin / unpin / lock / unlock / archive / restore / forget / remember / param / migrate / **delete**（需配置开关 + 确认） | 对单条的写向 mutation（含跨池搬移） | 🔲 缺口（底层 `_memoryOp` 已有）|
| `gc_report` 遗忘引擎报告 | 衰减 / 合并 / 摘要 / 迁移统计 | 生命周期治理 | 🔲 缺口（底层 `gc` 已有，需暴露 + 报告）|

> **Agent 面合计 = 读 7 / 写 2 / 管 3 = 12 个**（`tools/list` 现状 7 个条目：`recall_memory` / `write_memory` / `list_projects` / `get_preferences` / `get_write_status` / `list_memories` / `get_memory`）。

> `memory_op`（旧称）≡ `manage_memory`（本文统一用 `manage_memory`），为同一概念的不同命名。

## 4. 内部管线 / 外部组件（非 MCP 工具，但系统必备）

| 能力 | 归属 | 作用 | 关键约束 |
|---|---|---|---|
| 采集器 Collector | 内部 | 扫会话日志 → L0（全量） | 后台周期（5min），单轮上限 50 条，按标题切分 |
| 脱敏闸门 Desensitization Gate | 内部 · 服务端强制 | L0→L1 清洗 + 脱敏 | **必须跑在可信内核，不可放客户端**；fail-safe（疑敏不进共享）；强度 B+ 定向人工复核（D14），策略两者并用（D15），时机规则同步+模型异步（D16）|
| `routeL1` | 内部 | 脱敏后 L1 打 `project_id`（私人 / 共享）| 消费 L1 产物，天然满足"P-shared 仅收脱敏 L1" |

## 5. 串起来的不变式

1. **写永远落 L0**：`write_memory` 只产生加密原始归档，绝不直写 `P-shared` / `P-<user>`；共享内容只能由「脱敏后的 L1」经 `routeL1` 晋升。
2. **读按令牌作用域**：`recall` / `list` / `manage` 统一 `projectInScope`，越界即拒。
3. **共享 = 已脱敏**：管线顺序（脱敏先于分流）保证 `P-shared` 里只有脱敏 L1。

---

## 6. 相对标准 CRUD 的三处不同（记忆库特性决定）

1. **写被强制降级为"只落 L0"**：标准库的写是直接 INSERT；这里 `write_memory` 只产生加密原始归档，精炼 / 脱敏 / 分流全交给内部管线。Agent 永远不能直写 `P-shared` / `P-<user>`。
2. **共享是派生量而非主数据**：`P-shared` 的内容只能由"脱敏后的 L1 经 `routeL1` 晋升"，所以"管理"里没有"直接写共享池"的工具——这是脱敏闸门的内核强制结果。
3. **遗忘是一等公民**：标准库忙着存，记忆库必须能"忘"（衰减 / GC / 归档 / 删除需确认），所以 `gc_report` 和 `manage_memory(delete/archive)` 是管理档的核心而非附属。

## 7. 预期总数与落地难度（修正）

- **Agent 面 MCP 工具 = 12 个**（读 7 / 写 2 / 管 3）；`tools/list` 现状 7 个条目（批次44-D5-1 后）。
- **其中 8 个底层内核 API 已存在**（`recall_memory`/`write_memory`/`list_projects`/`get_preferences`/`browse`/`logs`/`gc`/`_memoryOp`/`_feedback` 对应物），属"接线暴露"低风险。
- **净新增或新变体**：`create_project`、`recall_memory(scope='session')`、`get_memory`、`list_memories`、`get_write_status`、`export/import`。
  > 批次44 进度：`get_write_status`（D4）、`list_memories` / `get_memory`（D5-1）已落地；`create_project` 经用户确认「并入 D6」，其余待 D5-2～D5-4。
- **内部管线**（Collector / 脱敏闸门 / routeL1 / 精炼管线）与**外部组件**（Token Broker）不是 MCP 工具，但为上述所有"写"与"共享读"的前提。
- 运维/管理端能力（§3）单独列管，不计入 Agent 面 12 之数。

## 8. 待确认缺口

1. **跨项目检索 / 全局搜索（`scope='user+shared'`）**：当前 `recall_memory` 仅单 `project_id`。多用户下"搜我所有可见池"建议作为 `recall_memory` 的一个 `scope` 取值（非新工具），仍受 `projectInScope` 逐池校验（D21/D24）。
2. **导出 / 导入（backup / archive）**：多用户下归档 / 迁移需要，但属管理 / 运维能力，建议走独立管理员 CLI / REST（复用 `fileStorage` + `l0Split` / `l0Recovery`），并配套密钥环处理；不作为普通 Agent 令牌可触发的 MCP 工具（D25）。
