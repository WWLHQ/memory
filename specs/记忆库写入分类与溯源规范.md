# 记忆库写入分类与溯源规范（草案）

> 目的：约定 Agent 写入记忆时的**分类法**、**写入卫生**、**source_agent 命名**、**user_id 取名原则**，解决多 Agent 并发写入下的可追溯性与召回质量。
> 配套文档：`记忆库工具能力清单.md`、`接入Agent行为规范.md`、`MCP运维与多Agent写入规范.md`。
> 本文为规范草案，不含实现代码；凡涉及落地均标注"待实现"。

---

## 1. 六类目用法（与代码 `CATEGORIES` 一致）

`types.ts` 的 `CATEGORIES = ['fact','decision','pitfall','insight','preference','context']` 与下面对齐，无需改枚举。

| 类目 | 用途 | 写法要求 |
|---|---|---|
| `fact` 事实 | 技术栈 / 架构 / 接口契约 / 状态，客观可验证，带证据 | 附可验证证据（版本、路径、契约片段）|
| `decision` 决策 | 关键决定 + 决策编号（如 `D12`）+「为何选 A 不选 B」 | 必带决策编号与选型理由 |
| `pitfall` 踩坑 | 必须「现象 → 原因 → 规避」三段 | 三段齐全，规避要可操作 |
| `insight` 洞察 | 可复用的规律 / 方法论 | 提炼为可迁移结论 |
| `preference` 偏好 | 用户 / 团队持久偏好；**同时进 `get_preferences`** | 持久、跨 Agent 共享；`agent.ts` 的 `getPrefs()` 正是 `category==='preference'` 过滤 |
| `context` 背景 | 目标 / 范围 / 边界，低频更新 | 低频，避免噪声 |

> 类目内的"三段 / 决策编号"做成**写入提示**（Agent 自觉遵循），**不强校验**——`content` 是自由文本，硬校验会挡住合法变体。

---

## 2. 写入卫生规则

1. **一条一主题、原子化、带关键词**（利于召回）。
2. **必填**：`user_id`、`source_agent`、`project_id`（注：`project_id` 在 `mcpSchema.ts` 中已是 `required`，与 `content` 并列，非"建议"）。
3. **建议带**：`session_id`（会话溯源）。
4. **纠错不删旧条**：常态不删；纠错时写新 `decision` / `pitfall`，在 `content` 开头标注「替代 `mem_xxx`」便于 recall 关联。`memory_op` 的 delete 仅限人工确认场景（配置开关 + 确认），不用于日常纠错。

## 4. user_id 全局约定 + 取名原则

**全局约定**：所有接入 Agent 用**同一个** `user_id`，使跨 Agent 的事实 / 偏好对齐。

**取名原则（逻辑）**：
- **锚定"人"，不锚定 Agent / 会话 / 设备**：`user_id` = 记忆归属的主体（人），`source_agent` = 谁写的，`session_id` = 哪次对话，`project_id` = 哪个项目 / 池。四元组各司其职。
- **稳定优先**：首次设置（setup 向导）生成一次、持久化，绝不随会话、重装（数据根保留）、设备改变。
- **匿名、不嵌个人信息**：不用邮箱 / 昵称（隐私 + 同步冲突风险），用匿名稳定 ID。
- **与私人池名派生绑定**：私人池名 `P-<user>` 直接由 `user_id` 派生 → 改名 = 换池 = 记忆搬家，故必须稳定。

**现状**：代码 `mcpAuth.ts` 的 `DEFAULT_MCP_ACCOUNT.user_id = 'u1'` 已是最简稳定匿名值，与全局约定吻合。本地优先单用户场景下 `'u1'` 即满足；若未来多用户，`user_id` 升为 `u_<稳定ID>`（如 `u_<ulid>`）即可，原则不变。

> 待实现：写路径把 `user_id` 从"会话派生（`sessionUser`）"改为"取全局固定值（如 `'u1'`）"，MCP 参数 `user_id` 标记必填（与全局约定一致）。

## 6. 附录：是否区分工作 / 情景 / 语义 / 长时记忆？

**结论：不必新增正交的"记忆类型"枚举，现有四维已覆盖；建议文档化映射，并用 `recall_session` 补足"工作记忆"。**

认知科学四类与现有模型的对应关系：

| 认知类型 | 现有模型中对应 | 说明 |
|---|---|---|
| 工作记忆（短暂、当前会话） | **`recall_session`**（按 `session_id`+时间窗，待实现）+ `decay_class=hot` | 当前缺口：`recall_session` 尚未实现，是补足工作记忆的关键 |
| 情景记忆（具体经历 / 事件） | `pitfall`/`context` + L0 原文 + L1 | "现象→原因→规避"即一次具体情景 |
| 语义记忆（去语境化知识） | `fact` + L2–L6 精炼产物 | L0→L6 管线正是把情景蒸馏成语义的过程 |
| 长时记忆（持久） | `decay_class` 梯度（hot/warm/cold/archived/dormant）+ 持久化库 | 衰减模型即"短时→长时"的生命周期 |

**为何不另加 `memory_type` 字段**：
1. 与现有轴（layer=精炼深度、category=内容类型、decay=生命周期、session=工作记忆）**冗余且可能冲突**；
2. L0→L6 精炼管线自动把"情景（L0/L1）"产出"语义（L2+）"——显式类型会与管线打架；
3. 真有"只要语义事实"的需求，应是 **recall 过滤**（在现有字段上），而非新增存储维度。

**建议**：在行为规范里文档化上表映射，让 Agent 理解"语义记忆 = L2+ 的 `fact`"；把 `recall_session` 列为优先实现的缺口以补工作记忆。
