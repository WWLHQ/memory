# 开发纪律：每个原子动作收尾必须过 3 道闸门

> 用户 2026-11-05 明确要求并定为长期纪律：**每个原子动作收尾必须过 A·影响面回归 / B·效果验证 / C·变异验证 三道闸门**。
> 本文是单一真源；`AGENTS.md` §0 引用本文。任何原子任务（一个子任务 = 一个 commit）在提交与「展示等确认」之前，
> 必须给出三道闸门各自的**命令/用例/数字证据**，缺一即视为未完成，不得提交、不得宣称完成。

---

## 0. 为什么要有第三道闸门

全量测试全绿只能证明「已知用例没被破坏」，不能证明「用例真的能抓到错误」。
前两道闸门回答「改动有没有伤到别处 / 改动有没有生效」；第三道回答
**「如果有人把实现改错一点点，这套防线会不会响」**。没有 C，A 与 B 都可能建立在
一组恰好永远为真的弱断言上（例如只断言 `isError === true` 却没断言库状态未变）。

---

## 1. A · 影响面回归（Impact Regression）

**问题**：这次改动可能伤到哪些既有行为？必须逐一证明没有伤到。

必做项：

| # | 检查 | 判据 |
|---|---|---|
| A1 | 列出影响面清单 | 所有调用点、两端 TCP(8202)/HTTP(8204)、端壳/UI、存储序列化兼容、审计格式、内核公开契约类型；改 `types.ts` 接口时须列出全部实现/调用点 |
| A2 | 全量回归 | `npm run test:gate`（4 分片串行；仅原生崩溃 `0xC0000409` 重试一次，断言失败绝不重试/不吞；JSON 报告留档 `test-results/test-gate/`），记录文件数 / 用例数 |
| A3 | 受影响套件单跑 | 单独跑受影响文件，记录套数 / 用例数（便于定位） |
| A4 | 静态门禁 | `npm run typecheck`（含 electron 工程）0 错；受影响文件 `npx oxlint` 0 warnings / 0 errors |
| A5 | 索引一致性 | `npm run code:index -- --write` 后 `npm run code:index:check` 通过；干净树提交后复跑一次 |
| A6 | 既有行为未变 | 明确点名「未改动」的既有路径（如 `ma.gc()` 默认行为、`_feedback` 端壳钩子、recall 默认档），并给出钉住它的回归用例名 |
| A7 | 提交卫生 | `git add` 只放本次相关文件，早期遗留/外部生成文件严格排除；提交后 `git status` 复核 |

**证据格式**：命令 + 实测输出数字（例：`174 文件 / 2089 项全绿`、`0 warnings / 0 errors`）。

---

## 2. B · 效果验证（Effect Verification）

**问题**：这次改动声称的效果，是否真的发生了？

必做项：

| # | 检查 | 判据 |
|---|---|---|
| B1 | AC 逐条对应用例 | 子方案里每条 AC 至少一条正向用例；涉及两端的工具必须 TCP + HTTP 各一条 |
| B2 | 断言「状态真的变了」 | 不能只断言「没报错」。要断言落库字段 / 版本 / 审计记录 / 回执字段的实际值（如 `decay_class='warm'`、`version=2`、`trust_delta=0.1`） |
| B3 | 断言「只读真的没变」 | 只读/演算类改动必须反向断言库状态与审计**未变**（如 `dry_run=true` 后 `queryAudit` 为 0） |
| B4 | 诚实降级 | 不存在 → `ok:false` + 原因；越界 → 明确拒绝；不伪造统计量、不补造空记录、不伪造审计回执 |
| B5 | 端到端而非仅单测 | 至少一条从工具调用（`tools/call` / TCP method）到存储/审计的完整链路用例 |

**证据格式**：用例名 + 关键断言值。

---

## 3. C · 变异验证（Mutation Verification）

**问题**：把实现故意改错一点点，防线会不会响？**必须至少各做一次 C1 代码级变异与 C2 输入/状态变异。**

### C1 代码级变异（注入缺陷 → 必须红灯 → 原样还原 → 必须绿灯）

1. 选一个**关键判定**（过滤条件、默认值、白名单、拒绝分支、字段裁剪）。
2. 临时把它改成「近似正确但错误」的版本，例如：
   - `m.session_id === sid` → `true`（本会话过滤失效，应返回别会话记忆）
   - `dry_run=true 不写审计` → 无条件写审计（演算不再只读）
   - `if (!projectInScope(...)) throw` → 删除该分支（越界放行）
   - `snippet` 白名单 → 追加 `content_l0_enc`（L0 泄漏）
3. 跑**针对该判定的测试**，必须**失败**（记录失败用例名与断言）。
4. **原样还原**源码，用 `git diff` / 文件哈希确认还原无残留，再跑同一批测试必须全绿。
5. 若注入缺陷后测试仍全绿 → 说明断言太弱，**先补测试再重做 C1**，不得直接提交。

> 执行纪律：变异只在本地工作树临时进行，禁止提交变异版本；还原后用 `git diff -- <file>` 确认与变异前一致。

### C2 输入 / 状态变异（负向矩阵）

至少覆盖：不存在、越界（受限令牌）、历史行缺新字段（向后兼容）、非法类型/边界值、
参数组合变异（如 `scope='session'` 但缺 `session_id`、反过来给了 `session_id` 却 `scope='project'`）、
以及「看似相似但不应命中」的数据（同项目不同会话、同会话不同项目）。
判据：系统**明确拒绝或如实空态**，绝不静默成功、绝不回显不可见数据。

### C3 纯文档 / 任务分配类原子动作如何过 C

不做代码变异，改做**反向核对**：把文档里每条声明逐条与代码、命令输出或任务清单状态对照；
任一条对不上即失败。并做一次「声明变异」——临时改动文档中的判据描述，
确认引用该判据的检查清单/交叉引用会失配（能被发现），随后还原。

**证据格式**：变异点、注入后的失败用例/失配项、还原校验（`git diff` 为空 + 测试全绿）。

## 4. 收尾记录模板（每个原子任务都要填）

```
A·影响面回归：影响面 = …；全量 = …；受影响套件 = …；typecheck = …；oxlint = …；index:check = …；既有行为回归用例 = …
B·效果验证：AC→用例映射 = …；状态/审计断言实测值 = …；端到端链路 = …；诚实降级 = …
C·变异验证：C1 变异点 = … → 失败用例 = … → 还原校验 = …；C2 变异矩阵 = …（全部如实拒绝/空态）
```

三栏写入：提交信息正文（精简版）、`specs/code-map.md` 对应小节、以及向用户展示的成果说明。
**每次展示成果时必须同时给出三栏证据并等待人工确认**，再进入下一原子任务。

---

## 5. 与既有纪律的关系

- 「先需求/方案定稿 → 再拆任务 → 再按原子任务实现与提交」不变；本文只约束**每个原子动作的收尾**。
- 「每原子任务一提交 + conventional commit（Why/What/影响范围 + Co-Authored-By）」不变。
- 「两端一致 / L0 不泄 / 诚实降级 / 不碰遗留脏文件」不变，分别归入 A1、B4、C2、A7。
- 三道闸门**不是**额外一轮全量测试：A 复用既有门禁，B 与 C 复用并补强用例；C1 需临时注入缺陷。
