## 一、已确定结论（DECIDED）

**D1. 不建独立物理文件/库来存储私人记忆。**
私人隔离靠"逻辑 `project_id` 分离 + 令牌作用域"，不是物理分库/分文件。物理分文件不增安全性（闸门是令牌非文件）、且增运维成本。

**D2. 隔离唯一闸门 = 令牌 `scope_project_ids` + 读写 `project_id`。**
`user_id` 在读取时**不隔离**——同 `project_id` 下所有记忆互相可见。故私人必须靠独立 `project_id`。

**D3. 三池模型。**
- 共享池 `P-shared`：团队共享知识，所有用户令牌都含。
- 私人池 `P-<user>`：每用户一个专属项目，仅该用户令牌含。
- 归档池 `P-archive`（可选）：离职/停用用户的私人池移入，普通用户令牌不含。

**D4. 登录 → 令牌代理 mint 受限令牌。**
用户 X 登录 → 令牌代理发 `scope_project_ids=['P-shared','P-uX']`。禁止静态 `['*']` 下发给真实用户/客户端。

**D5. L0 = 全量采集加密归档，不进任何池。**
L0 不进入 `P-shared` 也不进入 `P-<user>`；recall 只作用于 L1+。L0 仅持 L0 会话/管理封装可解密。

**D6. L1 = 清洗+脱敏后产物，是真实分流点。**
L0 →（清洗+脱敏）→ L1；脱敏后的 L1 才被分到私人池或共享池。

**D7. L1 分流实施路径 = 混合（Hybrid）。**
- 有显式意图 `for='team'`/`for='me'` → 直接定 `project_id`（最可靠）；
- 无意图 → 管线按 `category` + 残留个人标记自动分流；
- 低置信 → Agent 向用户确认一次。

**D8. L1 兜底方向 = 默认 `P-shared`。**
脱敏后内容已无秘密，共享收益大。

**D9. 不变式：`P-shared` 仅接收脱敏 L1。**
分流步骤只消费 L1 产物，绝不消费 L0；管线顺序保证"脱敏先于分流"（"共享 = 已脱敏"）。

**D10. 脱敏闸门必须跑在可信内核（服务端），且 fail-safe。**
不可放客户端/Agent 侧（否则可被绕过直接写 `P-shared`）。疑敏即不进共享。

**D11. 纠错：L1 已脱敏，跨池搬移用 `manage_memory`，不依赖 `delete`。**
误投共享的敏感内容按 §8.3 写替代条 + 强化脱敏；因 L1 已脱敏，搬移不泄漏。

**D12. 目标工具集 = 12 个 MCP 工具（读7/写2/管3）+ 内部管线 + 外部令牌代理。**
详见 `draft-tool-inventory.md`。

**D13. recall 仅单 `project_id` 内检索。**
"共享+私人"由 Agent 对 X 的会话做两次 recall（`P-shared` + `P-uX`）再合并（在 `scope='user+shared'` 未定前）。

**D14. 脱敏闸门强度 = B+定向人工复核。**
默认规则+模型（Tier3）fail-safe 路由（疑敏不进共享）；命中的高风险类目（金融/健康/法律）升人工复核（Tier4）。

**D15. 脱敏策略 = 两者并用。**
可抽取的秘密（一句里的某个 key）→ 片段级脱敏后共享（如"用 `[REDACTED]` 调 API 取 X"）；内容本身属个人的（私人对话、个人观点）→ 整条转 `P-<user>`。

**D16. 扫描时机 = 规则同步 + 模型异步。**
已知格式（密钥/身份证/邮箱…）用确定性规则**同步秒级拦**；模型上下文深扫**异步**补刀。写入路径不被模型延迟拖慢，且 fail-safe 默认进私人池、晋升需扫描通过。

**D17. 精炼管线 = 集中跑于可信内核。**
单一记忆服务处理所有用户的 L0→L1，脱敏闸门/`routeL1` 在中央统一强制；贴合 D10 可信内核要求，不变式与审计收口到一处；L0 仍按用户分区访问。

**D18. 私人池 ID 命名 = `P-<user_id>`**（如 `P-u1`）。**
沿用 `P-` 前缀约定；保留 `P-u*` 前缀给私人池，规避与业务项目 ID 碰撞。

**D19. 令牌代理 = 外部 IAM。**
现有身份系统在登录时 mint 受限令牌（`['P-shared','P-uX']`）；记忆服务只消费、只做 `projectInScope` 校验，不内置 mint 逻辑。

**D20. 管理员令牌 = 外部 IAM 加 `is_admin` 声明。**
管理操作（`create_project` / `P-archive` 访问 / 撤销他人令牌）校验令牌中的 `is_admin` 声明；复用 §14.3 作用域模型 + 显式标记。

**D21. 召回支持 `scope='user+shared'`。**
`recall_memory(scope='user+shared')` 一次返回 `P-shared` + `P-<user>` 合并结果；Agent 不再两次调用+合并（扩展 `recall_memory`，类 §6 `scope='session'`）。

**D22. 私人池跨设备 = 按人不按设备。**
`P-<user>` 对同用户的所有 Agent/设备可见，私人记忆跟着人走，不绑某台设备。

**D23. `create_project` 本期不开 MCP 工具。**
私人池由外部 IAM/令牌代理在用户 onboarding 时建（或管理员脚本/管理端）；建池绑定入职，不暴露为 Agent 会话内工具。

**D24. 跨项目检索 / 全局搜索 = 需要。**
在 `scope='user+shared'` 之外，增加跨所有可见项目的聚合检索能力（聚合 + 跨池排序）作为扩展项。

**D25. 导出 / 导入 = 需要。**
提供 `export`/`import`（按池 / 按用户 / 全量），支撑离职归档（`P-uX`→`P-archive`）、合规导出、灾难恢复；与 D3 归档池、D11 跨池搬移配套。
