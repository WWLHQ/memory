## 3. 证据不足率 66.75% 的口径陷阱（本次结算最关键的一条）

计划 §1 写的是「所有命中分都 <0.3 的比例」。一周窗口的 `evidence_thin` 字段正是按**旧口径 `score < 0.3`**落盘的，但这条口径在 11-22 已被独立修复：

- 提交 `18a404c fix(memagent): 档位B证据不足判定改用纯相关度 relevance，停用 thin→w_i 自生长`。
- 源码 `src/core/memagent/agent.ts:54-62` 的判据注释（原文）：
  > `score = relevance × 四分量乘数`，而 importance 99.5% / half_life_days 100% / confidence 74% 缺失让乘数中位塌到 0.774，把 82.3% 的相关命中误判成 thin（真零命中仅 5.3%）。relevance 不受字段缺失污染；真实账本模拟：score<0.3 → 61.4%，relevance<0.3 → 4.0%。
- 现行口径 `isEvidenceThin(scored) = scored.every(s => s.relevance < 0.3)`。

**因此**：窗口里的 66.75% 与源码注释里的「61.4%」是同一类假象（字段缺失把乘数压塌，非语义弱），真实的语义证据不足率约 4%，**达标**。这一项不能作为「走 B」的触发证据——它是统计口径缺陷，不是召回质量问题。

**必须诚实标注的边界**：一周窗口的逐条 `relevance` 值未在审计里落盘（当时只落了布尔 `evidence_thin`），所以「≈4%」引用的是 11-22 修复时用真实账本做的模拟值，**不是对本窗口 394 条的逐条重算**。若要求绝对严谨，需补一次带 relevance 字段的采集，但那属于新观察，不改变本次「A 方案在覆盖率/未命中率/延迟/重复 query 四项上达标」的判定。

## 5. 观察项：平均命中数持续下滑

平均命中数从基线 4.16 → 一周 1.71，快照序列也显示逐日下滑（4.16→3.69→3.29→2.93→2.71→2.55→2.45→2.37）。计划未给它设阈值，故不触发升级；但需记录判断：

- 这与 top1 覆盖率从 0.056 升到 0.388 是**同一个变化的两面**：A 方案的覆盖率融合把「最相关的顶上来」，同时把弱相关尾部压掉，命中数下降是预期内的筛选效应。
- 用户 query 多为长关键词堆叠（如「管理员与成员权限设计 静态门禁 索引重建…」），长 query 下能有三条以上真相关记忆的场景本就不多。
- 1.71 条/次偏低但未伤及 top1 准确率（0.388）与未命中率（5.58%），**不建议仅为抬高命中数而放宽候选阈值**。
