## 第一部分 · 对比点汇总

### 1.1 一句话结论

外部是**「宿主插件 + 服务端黑盒语义引擎」**——LLM 抽事实 / 1024 维 bge-m3 / reranker 全外包，自己只做客户端整形；我们是**「独立产品 + 自研记忆内核」**——分层、去重合并、衰减、召回模式、预算、加密、审计、成本记账全部自研，代价是**语义检索弱（64 维 hash 词袋）+ 无时间语义**。互补性极强：它的「结果整形层」值得抄，我们的「治理层」它没有。

### 1.2 逐维度对比

| 维度 | Hindsight（外部） | MultiAgent Memory（我们） | 判定 |
|---|---|---|---|
| 形态 | dsh 插件，自动装 uv/Python，拉起 8888 | Electron 桌面产品 + MCP(8204) + 22 个 HTML 入口 | 我们是完整产品 |
| 语义检索 | bge-m3 1024 维 + bge-reranker + LLM 事实抽取（联网/密钥/费用） | `JsVectorBackend` 64 维 hash 词袋 + cosine + 中文 2-gram，零模型/零出网 | **最大鸿沟，也是最大卖点差异** |
| 数据模型 | 事实 + chunk 原文 + document_id | L0 密文 / L1 脱敏 / L2 摘要 / L3–L6，含 decay/merged_into/墓碑 | **我们远 rich** |
| 时间语义 | `timeparse.js` 本地时区戳 + `query_timestamp` + 时间窗 ±1 天加权 | 时间仅影响半衰期；已写代码但未接入审计（见第二部分） | **原为明确空白，本轮已补代码** |
| 结果保真 | 按 chunk 拼回原文 + supersededIds 新旧覆盖 + 标识符精确词加权 | L2 摘要原样拼；已有影子探测 + source_excerpt（覆盖 34%） | 部分追平 |
| 写入 | 5 Hook 自动抓 + sha1 去重 + 失败不推进游标 + 429 退避 | MCP 写入 + pending 队列「pending≠成功」+ 发件箱待判 | 我们诚实语义更强，对方续传更完整 |
| 防回灌 | 三处切断（source.kind / 跳过 plugin: / 剥离 memory-context） | 不自动注入，回灌风险本就低 | 我们无需照搬 |
| 注入形态 | `<memory-context>` 合成 user 消息自动注入 + 免责头 | 回显三档 + 铁律「原样输出 display.markdown，数字/金额不得改写」 | 口径不同，不能照搬 |
| 安全 | owner-only 路由 + .env 密钥 + 日志脱敏 | 令牌三池门禁 + L0 双锁 + append-only 审计 + 0600 | **我们明显更重** |
| 可观测 | 25s 长轮询状态卡 + OpTracker | 回显统计 + cost/saved 记账 + 明细页 + CI 四门禁 | 对方贴实时状态，我们贴工程治理 |
| 隐私/成本 | 对话原文发第三方；992 轮约 ¥2.36 | 全本机零费用；`pipeline_llm_tokens=0` | **我们硬优势** |

## 第三部分 · 待实施方案（具体，按档位）

> 以下均为**方案**，未获确认前不实施。每项都是独立原子任务：展示成果 → 等确认 → 再下一步。

### P0 · 纯逻辑、零外部模型（优先级最高）

**P0-1 时间窗闭环验证（承接已改代码）**
- 现状：代码已改但未生效，审计 0 条。
- 做法：走交付闭环（关端→打包→验产物→启端→核运行态），用带时间词 query 实测。
- 验收：`audit.jsonl` 出现 `query_timestamp` / `time_window` 字段，时间词 query 占比约 15% 中有对应记录。
- 成本：零新依赖；风险：需重启桌面端。

**P0-2 source_excerpt 覆盖率 34% → 90%**
- 现状：仅 1935/5699 条有摘录，L2–L6 填充路径不全。
- 做法：检查 `coreWrite.ts` / `forgetting.ts` 填充逻辑，冲突/merge/精炼三路都补；L0 密文恒不进（安全红线）。
- 验收：按层统计覆盖率，L2–L6 均 >85%；`sourceExcerpt.test.ts` 增补 L0 排除断言。

**P0-3 权重调优，证据不足率 51% → <40%**
- 真源：`shared/growthConfig.ts`（0.35/0.30/0.15/0.20），`forgetting.ts` 仅转发。
- 做法：离线 NDCG 评估（复用 M1-2 的 `mems_detail`，不重跑向量检索）→ 只出建议不写 `growth:v1` → 人工采纳后再落库。
- 验收：一周快照 `recall-snapshots.jsonl` 证据不足率下降、top1 覆盖不回退。
- 边界：**遵守「不为一周数据调参凑数」约定**，只在评估确有收益时动。

**P0-4 反馈闭环（当前 1/679 反馈率）**
- 做法：把「有用/没用」按钮默认可见，反馈入口前置到回显交互位。
- 验收：反馈率 >5%，feedback 工具计数可查。

### P1 · 需架构改造（先评估再动手）

**P1-5 BM25 长度归一化（解决长文被稀释）**
- 现状：纯 cosine 分母含正文长度，长文（>1500 字）Recall@5 仅 1.6%。
- 做法：在 `fuseRelevance` 之外加 BM25 length norm 作为第三路融合信号，λ 可配；保留 λ=0 逐字等于旧行为。
- 验收：长文分组 Recall@5 从 1.6% 提升到 >15%，短文不回退。

**P1-6 本地 ONNX embedding（64 → 384 维）**
- 方案：评估 `onnxruntime-node` + `multilingual-e5-small`，与 64 维并行、逐步迁移；仍纯本地零费用。
- 风险：架构级变更，包体积上升；**须用户决策后才启动**。

**P1-7 本地 cross-encoder reranker**
- 方案：对 top-20 候选重排序，预计 top1 覆盖 45%→70%。
- 前提：P1-6 落地后再评估。

**P1-8 延迟优化 p95 1141ms → <500ms**
- 做法：`qvec` 按 query 文本缓存（LRU）；冷层副本常驻索引；避免每次全表 embed。
- 验收：p95 下降 >50%，命中率不变。

### P2 · 远期可选

- 知识图谱构建（实体关系）——我们 L0–L6 + merged_into 已有雏形，收益待评估。
- 多模态记忆（图片/语音）——双方均为纯文本，属新赛道。
- **明确不做**：接第三方 LLM/embedding/reranker（推翻零费用卖点）、自动装运行时（违反纯净度）、回显层第二套词表（违反单一真源）。
