# Agent 界面内联记忆标识 — 设计规格（19.7）

> 配套：《需求规格书》第 19 章、《需求规格书_UI页面设计》。
> 目标：让**终端用户在 Agent 原界面里直接看到"这次回答/这次省 token 是记忆助手的功劳"**，把"外挂记忆层"从后台概念变成用户可见的功劳证明。

## 0. 设计原则

1. **不打断**：标识是轻量内联标记，不弹窗、不阻塞 Agent 输出；用户可一键折叠。
2. **可归因**：每个标记都能点到「贡献了什么、花了/省了多少 token、依据哪条记忆」。
3. **可干预**：用户可直接在标记上「忘记这条 / 记住这条 / 标错」（17.3 / 13.7），形成反馈闭环。
4. **诚实**：证据不足时**主动显示**"证据不足"而非硬猜（2.4.3 `evidence_thin`），让用户知道系统没瞎编。
5. **对终端用户透明可开关**（19.1）：Agent 端可配置「显示记忆标识 = 开/关」，默认开。

## 1. 四类内联标识

| 标识 | 触发时机 | 显示位置 | 功劳点 | 规格书 |
|---|---|---|---|---|
| **① 记忆注入标记** | Agent 回答里用到召回记忆 | 答案段落内联小标 `🧠` + hover 弹层 | "这条事实来自记忆库第 N 条" | 19.5 / 9.5 |
| **② Token 节省标记** | 一次召回的 payload vs 全量 | 回答底部一行统计 `⚡ 本次召回省 X token` | "没把全文塞给你，只取 Top-K" | 2.4.1 |
| **③ 背景免重复标记** | 新会话开始自动带项目上下文 | 会话头部 `📎 已带项目背景（N 条）` | "你没再贴一遍项目说明" | 9.1 |
| **④ 老化/证据警示** | 命中记忆过期或证据不足 | 对应答案内联 `⚠️` | "这条可能过时，已提示校验" | 9.6 / 2.4.3 |

## 2. 标识字段级规范

### 2.1 记忆注入标记（①）
| 字段 | 说明 | 控件 |
|---|---|---|
| 内联图标 | `🧠` 小标（不抢正文） | hover 展开弹层 |
| 弹层内容 | 命中条 `memory_id` + 摘要（L2 占位符 ≤200t，cold 条不给 L1 原文，15.3） | 弹层 |
| 衰减层 | `decay_class` 温度点（hot/warm/cold/dormant） | 颜色点 |
| 老化提示 | `aging_hint`（9.6：45 天前→"代码可能已改动，请校验"） | 黄色小字 |
| 命中片段定位 | 该条中与本次 query 相关的关键句高亮 | 高亮 |
| 可干预操作 | 「忘记」「记住」「这条记错了」（→13.7 反馈，trust_delta） | 弹层按钮 |
| 归因链 | 点 `memory_id` / `request_id` → 审计页 | 跳转 |

### 2.2 Token 节省标记（②）
| 字段 | 说明 |
|---|---|
| 实际 `payload_tokens` | 本次召回注入的记忆 token |
| 全量基线 | 若不裁剪的全量 token（对比值，用于算"省了多少"） |
| 节省额 | = 全量 − 实际（极简/占位符/裁剪共同贡献） |
| 归因分解 | 省来自「极简短查询」「L2 占位符注入」「超支裁剪」哪几项（2.4.3 / 2.4.1） |
| 展示 | 一行 `⚡ 本次省 1,420 token（极简 + 占位符注入）`，hover 展开分解 |

### 2.3 背景免重复标记（③）
| 字段 | 说明 |
|---|---|
| 注入条数 | 新会话自动带入的项目上下文条数（9.1 `load_project_context`） |
| 内容摘要 | 技术栈/约束/最近决策（折叠可展开） |
| 展示 | 会话头部 `📎 已带项目背景 8 条（技术栈·约束·近5决策）`，点展开 |

### 2.4 老化/证据警示（④）
| 字段 | 触发 | 文案（9.6 / 2.4.3） |
|---|---|---|
| 记忆过期 | `aging_hint` 非空 | `⚠️ 这条是 45 天前记录的，代码可能已改动，请校验后再使用` |
| 证据不足 | `evidence_thin=true` | `⚠️ 证据不足，已补查 Cold 层 / 建议切事实优先重试` |
| 可操作 | — | 「我确认这条仍有效」（confirm +0.1）/「确实过时」（reject −0.05 → 9.10 stale） |

## 3. 归因闭环（让用户知道"功劳"可量化）

```
Agent 内联标记（①②③④）
   │  每次回答带 1 行「记忆贡献摘要」
   ▼
用户当场看到：来自哪条记忆 · 省了多少 token · 是否过期
   │  用户点「记住/忘记/标错」
   ▼
13.7 反馈 → trust_delta + 7.2 自生长优化
   │
   ▼
审计页（request_id）可还原：这条功劳 = 哪次召回、注入了什么、省了多少
```

## 4. 可开关与降级

- **Agent 端配置**（UI 第 10 页新增）：`show_memory_attribution`（默认开）、`attribution_level`（full / token_only / off）。
- **降级**：宿主不支持内联标记时（老 Agent），退化为「回答前一行统计 + 可点展开」，不阻塞主输出。
- **诚实约束**：`evidence_thin`/`aging_hint` 为**必须显示**项，不可被"关闭标识"选项关掉（避免系统隐瞒不确定），只能调详略。

## 5. 验收用例（摘要）

| 用例 | 期望内联表现 |
|---|---|
| 回答用了记忆 | 答案段带 `🧠`，hover 见 memory_id + L2 摘要 + 衰减层 + 可「忘记/记住」 |
| 极简召回 | 回答底 `⚡ 省 1,420 token（极简+占位符）`，hover 分解 |
| 新会话 | 头部 `📎 已带背景 8 条`，展开见技术栈/约束/决策 |
| 命中旧记忆 | 段内 `⚠️ 45 天前，请校验`，可 confirm/reject |
| 证据不足 | `⚠️ 证据不足`（不可关闭）+ 「切事实优先」按钮 |
| 关标识 | 仅剩 1 行统计（token_only）；evidence_thin 仍显示（诚实约束） |
