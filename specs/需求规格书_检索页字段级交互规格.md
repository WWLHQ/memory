# 检索页 — 字段级交互规格

> 配套：《需求规格书》《需求规格书_UI页面设计》第 1 章。
> 本文件把检索页每个控件的**默认值、校验、联动、异常态文案、边界约束**定死到字段级，供开发与验收直接对照。
> 章节号引用以规格书为准；所有字段默认值/阈值可在「开发者模式」覆盖，但运行时仍以配置块 `mode_weights`/`mode_dispatch` 为准（可热更新）。

## 0. 页面状态机

```
IDLE ──提交──> LOADING ──成功──> RESULT ──改参数重查──> LOADING
                  │ 失败(超时/硬熔断/无记忆)
                  └─> ERROR / EMPTY
```

- `IDLE`：首次进入，`mode`/`scene` 用默认值，无结果。
- `LOADING`：查询中，结果区骨架屏，查询栏禁用，预算面板隐藏。
- `RESULT`：有 `hits`（可能为空数组→`EMPTY`）。
- `ERROR`：超时 / 网络 / 硬熔断（payload>3000）。
- `EMPTY`：`hits=[]` 且未触发补查。

## 1. 查询栏（IDLE / RESULT 可编辑）

| 控件 | 字段 | 默认值 | 校验 | 联动 | 异常态文案 |
|---|---|---|---|---|---|
| 查询输入 | `query` | 空 | 非空（trim 后长度 ≥1）；中文 <30 字 / 英文 <12 词 → 标记「将触发极简」（2.4.4 工程约束4） | 输入实时算语言长度；scene=critical 且 <30 字 → 禁用极简提示 | 空查询禁用「检索」按钮 |
| scene 下拉 | `scene` | `default` | 枚举 default/task_start/history_query/critical（13.5 / 2.4.1） | 见 §1.1 scene 联动表 | — |
| mode 下拉 | `mode` | `null`（显示"自动"） | 枚举 null/top_insight/fact_first/event_replay/pattern_reasoning/minimal（2.4.3） | 见 §1.2 mode 联动表；默认"自动"= 发 `mode=null` 走 2.4.4 分流 | — |
| 检索按钮 | — | 启用 | `query` 非空时启用 | 点击 → LOADING | 超时文案见 §5 |

### 1.1 scene 联动表（2.4.1 场景化预算 + 2.4.4 候选集）
| scene | 预算 | 默认模式（零命中） | 默认回灌深度 | LLM 重排 | mode 下拉可用项 |
|---|---|---|---|---|---|
| default | 800 | 极简轻量 | L3+L4 | 关 | 全部（含极简） |
| task_start | 1200 | 顶层洞察优先 | 项目记忆 + 预加载 1 条 L5 | 关 | 全部 |
| history_query | 2000 | 事件复盘模式 | 允许 L2 占位符 | 候选多时开 | 全部 |
| critical | 2500 | 事实优先 | L2 + 校验 | **强制开** | **禁用 minimal**（16.5 硬规则，2.4.4 约束5） |

- 选 `critical`：`mode` 下拉里 `minimal` 置灰 + tooltip「合规场景禁用极简（16.5）」；重排闸门默认 ON。
- 改 scene 后若当前 `mode` 不在新 scene 候选内 → 自动回落为新 scene 默认模式并 toast「mode 已按场景调整」。

### 1.2 mode 联动表（2.4.3）
- 显式选某 mode → 发 `mode=<该值>`，跳过自动分流（2.4.3 裁决规则 1「用户指定 > 自动分流」）。
- 选 `自动(null)` → 引擎按 2.4.4（scene 候选 + 关键词）裁决，写审计 `mode_dispatch`。
- `mode=minimal` 且 `scene=critical` → 被 §1.1 禁用，无法同时选中。
- 极简为主模式时：横幅隐藏「次模式注入」折叠项（2.4.3「极简禁止任何次模式降级注入」）。

### 1.3 session 上下文（9.1 / 18.2-D）
- 默认自动继承当前 `session_id`（全局租户上下文，0.1）；高级选项可手动改绑或清空。
- `task_start` 场景下显示「已绑定项目 <project_name>」徽章（9.1 `load_project_context`）。

## 3. 结果列表（`hits[]`）

### 3.1 单条记忆行字段（17.4 / 9.5 / 15.3）
| 字段 | 渲染 | 说明 |
|---|---|---|
| `memory_id` | 行首 ID（点击开详情） | 18.2-B |
| `content`（层级摘要） | 主文案 | cold/dormant 条**只给 L2 占位符 ≤200t**（15.3 回灌限制），不可展开 L1 原文（2.4.2 规则 1） |
| `decay_class` | 温度徽标 | hot(红)/warm(橙)/cold(蓝)/archived(灰)/dormant(深灰)；cold/dormant 条带「补查」角标（15.3） |
| `pinned` | 钉图标 | 置顶条**永远排在列表最上**（17.8 免检进候选，AC-03），其余按 score 降序 |
| `locked` | 锁图标 | 豁免后台任务（17.4），在线召回正常参与；hover 说明 |
| `freshness` | 进度条 % | =0.5^(age/half_life)，17.5；下限 0.05 |
| `importance` | 进度条 | 0–1，下限 0.1 |
| `confidence` | 进度条 | 0–1，下限 0.05 |
| `score` | 右侧分数（0–1） | 按当前模式权重算（2.4.2 规则 4） |
| `tags` | 标签组 | — |
| `merged_from`/`merged_into` | 「合并自 N 条」可展开 | 17.9 合并谱系 |
| 冲突标记 | 黄色 ⚡ + 仲裁说明 | 命中 2.4.2 规则 6 时内置：`[冲突] A(层/来源/时间) vs B(层/来源/时间) → 本模式=<mode> → 裁定以 <Y> 为准` |

- 排序：`pinned` 置顶 → 其余按 `score` 降序；同分按 `confidence` 次级降序。
- 默认 Top K = 3–5（17.8 第二层建议值）；可展开「加载更多」最多到 Top 10。

### 3.2 单条行操作
| 操作 | 触发 | 行为 | 文案（17.3） |
|---|---|---|---|
| 查看 | 点行 | 右侧上下文面板展开该条 | — |
| 记住 | 点「📌 记住」 | 升 importance + 短期提 confidence → Hot | 「已提升这条信息的优先级。」 |
| 忘记 | 点「⌫ 忘记」 | 降 confidence/importance → Warm/Cold，不物理删除 | 「这条信息已降权，后续会较少主动出现。你可以稍后恢复。」 |
| 反馈 | 点「☆」 | 跳用户反馈页（页面 9）预填 `memory_id` | — |

| 字段 | 渲染 | 规格书 | 阈值行为 |
|---|---|---|---|
| `payload_tokens` | 进度条 X / 1500（软上限） | 2.4.1 | 1500 软上限触发裁剪（变色）；2000 告警（橙）；3000 硬熔断（红，拒绝召回→ERROR） |

| `rerank_applied` | 标记 + 闸门状态 | 17.8 / 13.5 | critical 强制开；高频低价值默认关；失败→`rerank_fallback` 回退第二层（17.8） |

| `breach_detail[]` | 列表（被裁层级/条数） | 2.4.1 裁剪顺序 | 文案「以下内容已超支被裁，未进上下文: <层级> × N 条」 |

## 6. 异常态文案

| 状态 | 触发条件 | 文案 | 可操作 |
|---|---|---|---|
| EMPTY | `hits=[]` 且未触发补查 | 「没有可靠的记忆证据。建议：换个说法，或切到「事实优先」模式扩大召回深度。」 | 「切事实优先重试」按钮（2.4.3 逃生阀提示） |
| evidence_thin（未命中补查） | 2.4.3 触发 ①② 且 15.3 补查也未命中 | 「无可靠记忆证据，建议升级模式或人工确认。」 | 同上 + 「人工确认」跳记忆管理 |
| evidence_thin（命中补查） | 2.4.3 补查命中 | 「证据不足：已追加 1 条 Cold 摘要作辅助参考。建议切事实优先模式重试。」 | 「切事实优先重试」 |
| ERROR（硬熔断） | `payload_tokens > 3000`（2.4.1 硬熔断） | 「召回超硬熔断上限，本次已降级为「无记忆」响应。请缩小范围或拆分查询。」 | 自动记审计；禁用检索 3s |
| ERROR（超时） | 请求 > 2s（12.1 延迟 p99 阈值） | 「召回超时，已回退到第二层轻量打分结果。」 | 重试按钮 |
| critical + evidence_thin | scene=critical 且 evidence_thin（2.4.3 边界约束3） | 「合规场景证据不足：已强制开启 LLM 重排，建议切事实优先 + 重排确认。」 | 「切事实优先+重排」 |

## 7. 字段级校验规则（前端表单层）

1. **query 必填**：trim 后空 → 检索按钮 disabled。
2. **语言长度检测**（2.4.4 工程约束4，`mode_dispatch: {min_len_zh:30, min_len_en:12}`）：
   - 中文：`query` 去掉标点 < 30 字 → 极简候选。
   - 英文：词数 < 12 → 极简候选。
   - 仅作为「触发极简」信号展示，不阻止提交。
3. **scene 枚举**：非法值回落 `default`。
4. **mode 枚举**：非法值回落 `null`（自动）。
5. **critical 禁极简**（16.5 / 2.4.4 约束5）：scene=critical 时若 mode=minimal → 强制改 `null` 并 toast。
6. **二次查询保持上下文**：改 `mode`/`scene` 重查时保留 `session_id`，`request_id` 每次新生成（不复用，18.2-E 一次请求一个 ID）。

## 8. 边界约束（实现红线）

| # | 约束 | 来源 |
|---|---|---|
| R1 | `user_id`/`enterprise_id`/`team_id` 只来自全局租户上下文，前端**禁止手填** | 18.2-A / 0.1 |
| R2 | cold/dormant 条在列表与上下文面板**只呈现 L2 占位符**，L1 原文仅「审计展开」 | 15.3 / 2.4.2 规则1 |
| R3 | `pinned` 条免检直接进候选，永远列表最上 | 17.8 / AC-03 |
| R4 | `locked` 条在线召回正常参与，仅后台任务豁免 | 17.4 |
| R5 | critical scene 禁用极简、重排强制开 | 16.5 / 2.4.4 约束5 |
| R6 | 极简主模式禁止次模式降级注入 | 2.4.3 |
| R7 | 切模式只发生在**下一次请求**（用户显式带 `mode`），本请求不自动切 | 2.4.3 逃生阀设计说明 |
| R8 | `request_id` 必须可跳转审计页并展开全链路 | 18.2-E / 4.3 |
| R9 | 预算三档 1500/2000/3000 分别对应裁剪/告警/硬熔断 | 2.4.1 |
| R10 | LLM 重排失败不阻塞，回退第二层结果，记 `rerank_fallback` | 17.8 / 4.3 |

## 9. 验收用例（摘要）

| 用例 | 输入 | 期望 |
|---|---|---|
| 自动分流透明 | query="P0 故障,核对昨天发布三模块有没有报错", scene=critical | 横幅 mode=fact_first（事实 3 分命中），critical 禁极简，重排 ON（2.4.4 示例） |
| 短查询极简 | query="修一下这个空指针"(7 字), scene=default | mode=minimal，只召 L3+L4 ≤600t，横幅无次模式注入（2.4.4 示例） |
| 极简逃生阀 | minimal 且 L4 零命中 | 横幅黄警示 + 15.3 补查（Cold sim≥0.85/dormant≥0.9）+ 「切事实优先重试」按钮 |
| 预算裁剪 | 命中多导致 payload>1500 | 按当前模式裁剪顺序删，`budget_breach=true` + `breach_detail` 列出被裁层级 |
| 硬熔断 | payload>3000 | ERROR「降级为无记忆响应」，记审计 |
| pinned 置顶 | 存在 pinned 记忆 | 无论 score 一律排第一 |
| cold 条 | 触发 cold_recall | 该行只给 L2 占位符 + 「补查」角标，不可展开 L1 |
| request_id 追踪 | 点横幅 request_id | 审计独立窗口打开并定位该 ID 全部行 |
